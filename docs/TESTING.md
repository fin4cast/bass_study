## Текущая версия и регрессии

Из корня репозитория после установки корневых зависимостей:

```powershell
npm.cmd run check
npm.cmd run test:unit
npm.cmd run build
npm.cmd run test:browser
npm.cmd run test:training
npm.cmd run test:audio
npm.cmd run test:storage
npm.cmd run test:release
npm.cmd run test:ear
npm.cmd run test:harmony
npm.cmd run test:notation
npm.cmd run test:tracks
npm.cmd run test:input
npm.cmd run test:uiux
npm.cmd run test:design
npm.cmd run test:rhythm
npm.cmd run docs:check
```

Модульный набор проверяет музыку, вопросы/сессии/последовательности, self-report, аудиоплан, схему/миграцию и очередь. `test:browser` проверяет гриф, `test:training` — задания и предпросмотр, `test:audio` — звук и плеер, `test:storage` — базу и UI, `test:release` — обновления и одного писателя. Продуктовый ритм проверяет `tests/rhythm-browser.mjs`, а `test:harmony` содержит fixture-сценарии прежнего аудиодвижка. Исторические 191 unit и 87 браузерных сценариев зафиксированы в [P6](verification/P6.md).

P7-00 отдельно проверил изменённый data/UI-путь и release-регрессию; состав, целевой unit-снимок и локальные измерения — в [P7-00](verification/P7-00.md). Наличие unit само по себе не закрывает пользовательскую приёмку: дополнительные нотация/PCM/capture/UI проверяются отдельными runners, итог — [P7-04–06](verification/P7-04-06.md).

По умолчанию нужен свободный 4173 и установленный Edge; дополнительные fixture-порты: 4181 audio, 4182 storage, 4183 release, 4185 ear, 4187 harmony, 4192 input, 4193 tracks, 4194 notation. Runner владеет своим сервером/чистыми профилями, отключает кеш и блокирует внешние HTTP-запросы страниц. Команды последовательны. Занятый пользовательский сервер нельзя завершать ради проверки: все текущие продуктовые runners допускают только явный `--reuse-server` после точного сравнения GET200 `/` с `dist/index.html`. Такой сервер не закрывается/перезапускается, владение отражается в raw. Результаты — игнорируемый `test-results`, снимки прошлых этапов остаются неизменны.

В приёмке R-016 использовались `npm.cmd run test:ear -- --reuse-server`, аналогично storage/release: существующий preview не затрагивался. Перезапуск всего тестового браузера проверен; перезапуск внешнего сервера намеренно не выполнялся (`serverRestart:false`). Исторический настоящий server restart доказан в P6, код сервера не менялся.

Для воспроизведения модульного снимка именно P3, независимо от добавляемых тестов следующих этапов:

```powershell
npm.cmd run test:unit -- tests/music.test.ts tests/training.test.ts tests/results.test.ts --reporter=json --outputFile=test-results/p3-unit.json
```

`npm.cmd test` запускает весь текущий набор. При переносе JSON в документацию нормализовать абсолютные пути до относительных и отметить это в отчёте. Статусы, ошибки и число тестов не менять. Подробности нормализации зафиксированы в [отчёте P3](verification/P3.md).

Задания проверяются через видимую формулировку и действия пользователя, без скрытого правильного ответа из тестового API. Узкие фильтры делают ответ однозначным; для «найди все» видимая целевая нота сравнивается с независимой картой E-струны. Важны не только правильные ответы, но и исправление после ошибки, показ, пропуск, повтор позиции, недопустимый контекст и отмена сессии при смене режима.

Регрессия P2 сохраняет проверку музыкальных подписей, всех ладов и клавиатуры. Скринридер, Chrome и телефон не испытывались. Хранение продукта проверено отдельно на P5, а не объявлено готовым по историческому P1.

Все 12 продуктовых browser runners используют прежний строгий протокол reuse: явный флаг, read-only GET 200 `/`, побайтное совпадение с текущим `dist/index.html`, `owned:false`, запрет shutdown/restart чужого сервера. Итог UIUX — 9/9 сценариев с выборочным контрастом по computed styles/фактическим фонам; это не полная сертификация WCAG. ## Хранение и восстановление P5

После свежей сборки выполнить `npm.cmd run test:storage` (эквивалент — `node tests/storage-browser.mjs`). Runner использует production UI на 4173 и отдельный Vite/fixture на `127.0.0.1:4182`. Fixture импортирует фактические `src/storage` и training; её `window.p5` отсутствует в приложении. Проверки API обращаются к нативной IndexedDB Edge; временная память выделена в отдельный явно помеченный сценарий отказа исходного открытия.

Текущий runner проверяет схему 4, соседние записи без потери истории, upsert/delete, чистое восстановление и полную замену, отмену/ошибки валидации, транзакционный abort после уже успешного put, нативный отказ квоты и сохранность после полного закрытия/нового запуска Edge с тем же временным профилем. Часовой пояс и исходная локальная дата сохраняются; версия 1 исторического P5 не переписывается.

Квота задаётся реальным `Storage.overrideQuotaForOrigin` через CDP, физический диск не заполняется. Нативный отказ проверяется до заполнения базы пользовательскими записями: уже заполненная база может иметь зарезервированное место и принять малую запись даже при новом лимите 1 байт. Поэтому этот случай не заменяет отдельную проверку rollback заполненного снимка после успешного put. UI-сценарий отдельно проверяет видимую ошибку и успешный повтор после снятия ограничения.

В продукте через контролы проверяются автосохранение/перезагрузка, пресеты, загрузка JSON, preview/отмена/подтверждение, повреждённый файл, единственная запись завершённой серии, self-report с реальным временем эталона/расходованием длительности, фильтры истории, точный повтор ошибок в исходном контексте, ошибка/повтор и память с экспортом. В приложении не добавляется тестовая история или скрытый API правильных ответов.

Для воспроизведения модульного снимка P5 без будущих тестов:

```powershell
npm.cmd run test:unit -- tests/music.test.ts tests/training.test.ts tests/results.test.ts tests/audio-plan.test.ts tests/storage-model.test.ts tests/write-queue.test.ts --reporter=json --outputFile=test-results/p5-unit.json
```

Итог исторического P5: 168 unit и 16 браузерных проверок; среда/ограничения — в [P5](verification/P5.md). В `P5_UNIT.json` нормализованы только абсолютные пути; raw JSON скопирован без изменения. Регрессии после P5: [P2](verification/P5_REGRESSION_P2_EDGE.json), [P3](verification/P5_REGRESSION_P3_EDGE.json), [P4](verification/P5_REGRESSION_P4_EDGE.json). На P6 этот набор повторён для схемы 2; миграция и одна пишущая вкладка проверены отдельно.

### Дополнение P7-00: кеш, реальные чтения и масштаб

Нативные ожидания читаются через `fresh:true` и независимый raw IDB, чтобы кеш не скрывал ошибку записи. Отдельно проверены замороженная идентичность кеша, внешний синтетический писатель/явный fresh, шесть успешных мутаций без нового полного чтения, прежний кеш/raw после abort/quota и настоящее неожиданное закрытие базы через CDP `Storage.clearDataForOrigin`. Очистка допускается только для временного изолированного fixture-origin. Наблюдатели нативных read-методов считают вызовы и возвращают оригинальные результаты; данные и исключения не подменяются.

UI проверяет открытие истории с последними собственными commit и upsert частичного/исправленного результата с одним UUID. Фактический продуктовый scale-прогон — `node experiments/p7-scale/run.mjs --after-fix`, свободный порт 4184. Его нельзя смешивать с исходным candidate, который менял отдаваемые Vite тексты. Послеисправление не подменяет модули; проверяются точный roundtrip, кеш/abort, закрытая/открытая панель и отдельное первое полное чтение. Методика/пределы — [scale README](../experiments/p7-scale/README.md) и [P7-00](verification/P7-00.md).

## Слух и активный маршрут R-016

`npm.cmd run test:ear` запускает production UI на 4173 и fixture на 4185; `window.p7ear` существует только в fixture. Три независимых PCM-примера измеряют частоту по samples/переходам через ноль, начала по RMS-окну, паузу и хвостовую тишину. Live-проверки отдельно смотрят реальный сигнал и AudioContext-clock, stop/cancel/restart и отсутствие раннего complete.

UI выбирает ответ из наблюдения **настоящих native oscillator.frequency.setValueAtTime**: тестовый initScript записывает два запланированных Hz, не читая скрытый правильный ответ приложения. Это отдельный oracle, не PCM-измерение. До конца cue проверяются disabled-ответы/отсутствие target/MIDI-атрибутов; replay/ошибка/показ/пропуск, отмена, смена раздела, interrupted-приватность истории, настройки, download/restore и отдельная статистика проверены действиями пользователя.

Маршрут проверяется чистым полным планом 600000 мс и реальными короткими интервалами: пауза исключена, resume/early next/stop сохраняют фактическое время, checkpoint не теряет draft/caret и ID. Native hidden выполняется настоящими вкладками в отдельном Edge/CDP `noDefaults:true`, уникальный профиль на каждый случай. Итоговая история этих двух native-сценариев читается readonly IndexedDB после статуса сохранения; обычные UI-сценарии продолжают проверять реальные скачивание/импорт. Ни clocks, ни `document.hidden` не подменяются.

Целевой снимок этого checkpoint, исключающий будущие прототипы:

```powershell
npm.cmd run test:unit -- tests/music.test.ts tests/training.test.ts tests/results.test.ts tests/audio-plan.test.ts tests/storage-model.test.ts tests/write-queue.test.ts tests/constraints.test.ts tests/ear.test.ts tests/cue.test.ts tests/route.test.ts --reporter=json --outputFile=test-results/p7-01-unit.json
```

Состав/числа, исправления тестовых предпосылок и пределы — [P7-01](verification/P7-01.md). Новые harmony/notation/pitch/tracks файлы не входят в эту приёмку. PCM/native свойства не доказывают физические динамики, слышимость человеком, задержку или исполнение на инструменте.

## Аудиопроверки P4

После свежей сборки выполнить `npm.cmd run test:audio` (прямой эквивалент — `node tests/audio-browser.mjs`). Runner запускает production UI на 4173 и изолированный Vite на `127.0.0.1:4181`; fixture импортирует фактические `src/audio/engine.ts` и музыкальный модуль. Тестовый `window.p4` существует только в fixture. Продуктовые проверки идут через обычные контролы и открытые состояния интерфейса.

Проверяются независимые ожидаемые PCM-начала баса/клика, отсчёт, длительности, фрагмент, немые такты, 2 и 4, подразделения, лестница и mute. Live-проверки отдельно подтверждают настоящий сигнал анализатора, фактический курсор в окне lookahead, непрерывную сетку после дробной паузы, раннюю паузу до старта, ручной BPM, отмену будущего, стоп/перезапуски и завершение по аудиочасам. Отменённый trace и события с будущим временем не считаются прозвучавшими.

UI-проверки покрывают фрагмент/валидацию, синхронные подсветки, блокировку структурных контролов, BPM/громкость, отсутствие визуальных подсказок, клавиатурные сокращения и их guards, смену контекста/режима, недопустимую область и узкий viewport. Реальное скрытие вкладки выполняется отдельным Edge/CDP `noDefaults:true`, без подмены `document.hidden` и без искусственного события. Для нестандартного расположения Edge можно задать `BASS_P4_EDGE_PATH`; повседневный профиль не используется.

Результат — `test-results/p4-edge.json` и скриншоты `p4-player-desktop.png`/`p4-player-narrow.png`. Подробные измеренные значения, исправления и ограничения — в [P4](verification/P4.md). Системный выход браузера приглушён: PCM/live-проверки не являются прослушиванием физических динамиков или измерением аппаратной задержки.

Сборка должна быть свежей: тесты запускают статический сервер собранного `dist`, а не dev-server. Порт 4173 перед запуском свободен. Тест сам создаёт и завершает локальный сервер; отдельно запускать его не требуется.

Для текущего набора нужен установленный Microsoft Edge в стандартном расположении Windows. Проверка реальной видимости также принимает путь к исполняемому файлу через `BASS_P1_EDGE_PATH`. Используются изолированные временные профили; повседневный профиль браузера и пользовательские данные не затрагиваются.

Результат команды — именованные сценарии, ненулевой код возврата при ошибке и JSON в `experiments/p1/results/edge-windows.json`. Этот каталог игнорируется Git. Зафиксированный результат этапа хранится отдельно в [verification/P1_EDGE_WINDOWS.json](verification/P1_EDGE_WINDOWS.json); обновлять его осознанно вместе с отчётом после успешного прогона.

## Состав проверок отдельного стенда P1

| Область | Что действительно проверяется |
| --- | --- |
| Запуск | Production-сборка на постоянном origin, пустой/отключённый сетевой кеш, запрет внешних HTTP-запросов при доступном loopback. Отдельный внешний запрос подтверждает работу запрета. |
| Порт | Второй сервер получает `EADDRINUSE`; первый продолжает отвечать, origin не меняется. |
| Звук | Пользовательский старт, два отсчётных события, последовательность шагов цикла, интервалы запланированных событий и наличие сигнала в анализаторе Web Audio. |
| Управление | Пауза сохраняет позицию и выключает сигнал; продолжение не повторяет отсчёт; смена BPM применяется к следующей ещё не отправленной четверти. |
| Видимость | Отдельный Edge подключён через CDP с `noDefaults:true`; переключение настоящей вкладки вызывает `document.hidden`, паузу и тишину. Возврат не возобновляет звук без команды. |
| Остановка | Отменены события, освобождён голос, после остановки нет сигнала и новых событий; три новых старта не удваивают расписание. |
| PCM | Настоящий `OfflineAudioContext`: шесть звуковых начал с заданными интервалами, сменой темпа и циклом; проверяются амплитуда и нулевой RMS после остановки. |
| Данные | Запись/чтение/экспорт; отказ повреждённого JSON, новой версии, неверного BPM и нарушенной ссылки до изменения данных. |
| Транзакции | Отмена без подтверждения; принудительный abort после успешного `put` с проверкой сохранения всего исходного снимка. |
| Восстановление | Полный перезапуск браузера с тем же профилем; импорт в чистый профиль; полная замена с удалением старых записей. |

Обычный запуск Playwright эмулирует фокус; он оказался непригоден для доказательства скрытия вкладки. Поэтому этот сценарий использует отдельный процесс Edge без стандартных CDP-переопределений, polling по таймеру и настоящее переключение вкладки. Подмены свойства `document.hidden` или искусственного события `visibilitychange` нет.

## Пределы результатов

- Запрет внешних запросов моделирует отсутствие интернета с доступным localhost. Сетевые адаптеры Windows не отключались.
- Системный звуковой вывод тестового браузера приглушён. Анализируются сигнал внутри Web Audio и PCM; динамики, удобство тембра, физическая задержка и игра реального баса не измерялись.
- Проверены Edge 157.0.4341.42 и конкретная Windows-среда. Chrome, Firefox, телефон, сон компьютера, смена аудиоустройства и длительные занятия не испытаны.
- Текущая схема 5 и реальные старые версии 1/2/3/4 проверены с сохранением событий/дат; quota/abort/clear/cache и один writer проверены отдельно. Физический диск не переполнялся; совместное редактирование/синхронизация устройств не реализованы.
- Синхронизация звука с грифом/ритм проверены на P4, базовый сквозной сценарий — на P6. P7-00 проверяет данные/кеш и синтетическую годовую модель; звук/PCM этим этапом повторно не испытывались, будущие модули требуют отдельной приёмки.

## Правила добавления проверок

Использовать R-014 как источник контрольных значений музыкальной модели. Для генератора проверять множество допустимых ответов и невозможные фильтры. Для проигрывателя проверять данные расписания отдельно от аудиосигнала и отображения. Для хранения — транзакции и переносимое восстановление. Для интерфейса — действия с клавиатуры и понятность результата.

Не переносить статус «пройдено» со стенда на соответствующее продуктовое требование целиком. Новая проверка должна подтверждать наблюдаемое поведение или риск, а не повторять формулу реализации в ожидаемом значении.

## Нотация, дорожки и диагностический вход: P7-04–06

После свежего build выполнить `npm.cmd run test:notation`, `npm.cmd run test:tracks`, `npm.cmd run test:input`; при подтверждённом чужом preview добавить `-- --reuse-server`. Fixtures работают на 4194/4193/4192 соответственно. Результаты: `test-results/p7-notation-edge.json`, `p7-tracks-edge.json`, `p7-input-edge.json`. Проверенный снимок переносится в `docs/verification/P7_04_06_*` после успешного прогона, без перезаписи прежних этапов.

- Нотация: настоящий SVG и геометрия линий/добавочных линий, E0→written E2, E5/A0, энгармонические буквы, альтерации внутри/после такта, крайние высоты, три длительности, keyboard/390 px/200%, ленивые локальные fonts/licenses. Отдельно фактический AudioContext/плеер ведёт повторяющиеся позиции, абсолютные индексы фрагмента, count-in/pause/stop/pulse-off. Одни правильные data-атрибуты не заменяют эту проверку.
- Дорожки: обычные независимые WAV идут через настоящий native decoder и OfflineAudioContext. Измеряются импульсы общего нуля/короткой дорожки/[A,B)/двух циклов, частота varispeed, независимые PCM-каналы mix, live-clock/seek/pause/restarts/finish/dispose. UI проверяет metadata-only JSON, SHA mismatch/переименование, reload/restore без буферов, ошибки/отмену и реальное hidden. Лимиты проверяются как предохранители, не как обещание памяти 512 МиБ.
- Вход: настоящие getUserMedia/fake-device с синтетическими WAV проверяют частоту/октаву/шум/гармоники/clipping, requested/getSettings, отсутствие слышимого routing, stop/dispose и явный доступ. Негативные permission/pending/ended/device cases различают нативный capture и управляемый тестовый триггер. Native hidden использует отдельный Edge без focus override и прекращает tracks; возврат не подключает их автоматически. Любая симуляция обозначается в raw, не выдаётся за физическое отключение USB.

Системный выход тестового браузера приглушён. Измерения PCM и fake-device не подтверждают физические динамики, настоящий бас/USB или сквозную задержку. Полный метод, исправления fixture/продукта и протокол реального инструмента — [P7-04–06](verification/P7-04-06.md).

## «Табулатура и ноты» P10-01 и схема 7

Это отдельные проверки **основного приложения** после утверждения VIS-06-A, а не повторное использование итогов эксперимента. Выполняются последовательно после актуального build из корня; фактически выполнены:

```powershell
npm.cmd run build
npm.cmd run test:unit -- --reporter=json --outputFile=test-results/p10-unit.json
node tests/music-bank-channels.mjs
node tests/music-bank-storage-browser.mjs --reuse-server
node tests/music-bank-browser.mjs --reuse-server
```

`music-bank-channels.mjs` загружает **продуктовый** `public/vendor/music-bank/alphaTab.js` и собственный channel helper. Перечень/SHA личной выборки используется только как вход проверки; в runtime продукта зависимости от `experiments` нет. Настоящие события/программы/транспозиция и PCM 65 непустых партий сравниваются с одиночными штатными партиями. Отдельные случаи покрывают choke, velocity 0, drum-program fallback и расширенные каналы. PCM не сохраняется; число 65 не включает пустую партию или ожидаемый отказ GTP.

`music-bank-browser.mjs` использует обычный продуктовый UI, локальные исходники и настоящий живой сигнал Web Audio с наблюдением только из test initScript. Покрывает 15 открытых файлов/один отказ, произвольный микшер и ноты/TAB, каталог реальной папки 48 602 файлов, поиск/страницы/чтение только выбранной песни, metadata-only JSON/пресеты/restore/rebind, pending-cancel, обе темы/прокрутку и настоящее native Edge/CDP-скрытие. Задержанный import после ухода проверяется с учётом исходного `suspended` Tone-контекста; отсутствуют поздние новые контексты/активация владельца. Продукт не получает скрытый test API. Автоматический вывод заглушён; это не испытание реального баса или акустики.

`music-bank-storage-browser.mjs` запускает отдельный native Edge/CDP-профиль для каждого из четырёх сценариев. Продуктовый origin сначала получает буквальную базу 6 с [профилем/черновиком/историей](../tests/fixtures/v6-backup.json), затем сам выполняет upgrade 6→7. Аборт вводится **после успешного native cursor.update** и проверяет откат версии/всех данных. Cache/fresh/readonly raw и restore с abort **после успешного put** проверяются на изолированной fixture с настоящей IndexedDB. Preview, отмена, плохие неактивные musicBank/preset не меняют подтверждённый снимок; экспорт после отказа не выдаёт кандидата за сохранённое. Память не подменяет IndexedDB.

Оба новых браузерных runner используют расширенный tracks harness: продуктовый 4173 и fixture 4193, новые временные профили, запрет внешних HTTP и проверку владения серверами. Их нельзя выполнять параллельно друг с другом или с `test:tracks`. `--reuse-server` разрешает только GET `/`, побайтно совпавший с текущим `dist/index.html`; чужой сервер не закрывается/перезапускается. Native удаление `bass-study` выполняется только внутри созданного тестового профиля, пользовательская база обычного профиля не затрагивается.

Raw P10-01 собраны в [отчёте P10](verification/P10.md) вместе со снимками «Студии». В этом прогоне общие 12 прежних browser runners дали 222/222 на схеме 7. В рабочей копии с P10-02 runner `music-bank-storage-browser.mjs` проверяет прямой переход 6→8 и сохраняет прежние проверки профиля, черновиков, кеша и метаданных партитуры.

## Продуктовый «Метроном и ритм» P10-02

На текущей сборке выполнить `node tests/rhythm-browser.mjs`. Для уже работающего совпадающего продукта используется `--reuse-server`.
