# Проверки проекта

Дата: 2026-11-08. Проверены технические механизмы P1, изучение грифа P2, экранные задания/маршруты P3 и продуктовый звук/ритм P4. Приёмка всего MVP ещё не выполнена; реализация отдельных требований отражена в REQUIREMENTS.

## Приложение P4 и регрессии

Из корня репозитория после установки корневых зависимостей:

```powershell
npm.cmd run check
npm.cmd test
npm.cmd run build
npm.cmd run test:browser
npm.cmd run test:training
npm.cmd run test:audio
```

Модульный набор проверяет чистую музыку, вопросы/сессии/последовательности, ручную модель self-report и аудиоплан. `test:browser` остаётся регрессией изучения грифа, `test:training` — заданий и предпросмотра, `test:audio` проверяет реальный аудиодвижок и плеер. Зафиксированные состав и числа — в [P2](verification/P2.md), [P3](verification/P3.md) и [P4](verification/P4.md), а не в архитектурных утверждениях.

Браузерные runner требуют свободный порт 4173 и установленный Edge; аудиопроверке также нужен свободный 4181. Каждый сам запускает/закрывает production-сервер, создаёт чистый контекст, отключает кеш и блокирует внешние HTTP-запросы страниц. Перед ними остановить вручную запущенный сервер; команды выполнять последовательно. Результаты пишутся в игнорируемые `test-results/p2-edge.json`, `p3-edge.json` и `p4-edge.json`, скриншоты — туда же. Проверенные снимки P4: [браузерный JSON](verification/P4_EDGE_WINDOWS.json) и [unit JSON](verification/P4_UNIT.json).

Для воспроизведения модульного снимка именно P3, независимо от добавляемых тестов следующих этапов:

```powershell
npm.cmd run test:unit -- tests/music.test.ts tests/training.test.ts tests/results.test.ts --reporter=json --outputFile=test-results/p3-unit.json
```

`npm.cmd test` запускает весь текущий набор. При переносе JSON в документацию нормализовать абсолютные пути до относительных и отметить это в отчёте. Статусы, ошибки и число тестов не менять. Подробности нормализации зафиксированы в [отчёте P3](verification/P3.md).

Задания проверяются через видимую формулировку и действия пользователя, без скрытого правильного ответа из тестового API. Узкие фильтры делают ответ однозначным; для «найди все» видимая целевая нота сравнивается с независимой картой E-струны. Важны не только правильные ответы, но и исправление после ошибки, показ, пропуск, повтор позиции, недопустимый контекст и отмена сессии при смене режима.

Регрессия P2 сохраняет проверку музыкальных подписей, всех ладов и клавиатуры. Скринридер, Chrome и телефон не испытывались. Постоянное хранение приложения требует P5; результаты технического P1 не закрывают его продуктовую приёмку.

## Аудиопроверки P4

После свежей сборки выполнить `npm.cmd run test:audio` (прямой эквивалент — `node tests/audio-browser.mjs`). Runner запускает production UI на 4173 и изолированный Vite на `127.0.0.1:4181`; fixture импортирует фактические `src/audio/engine.ts` и музыкальный модуль. Тестовый `window.p4` существует только в fixture. Продуктовые проверки идут через обычные контролы и открытые состояния интерфейса.

Проверяются независимые ожидаемые PCM-начала баса/клика, отсчёт, длительности, фрагмент, немые такты, 2 и 4, подразделения, лестница и mute. Live-проверки отдельно подтверждают настоящий сигнал анализатора, фактический курсор в окне lookahead, непрерывную сетку после дробной паузы, раннюю паузу до старта, ручной BPM, отмену будущего, стоп/перезапуски и завершение по аудиочасам. Отменённый trace и события с будущим временем не считаются прозвучавшими.

UI-проверки покрывают фрагмент/валидацию, синхронные подсветки, блокировку структурных контролов, BPM/громкость, отсутствие визуальных подсказок, клавиатурные сокращения и их guards, смену контекста/режима, недопустимую область и узкий viewport. Реальное скрытие вкладки выполняется отдельным Edge/CDP `noDefaults:true`, без подмены `document.hidden` и без искусственного события. Для нестандартного расположения Edge можно задать `BASS_P4_EDGE_PATH`; повседневный профиль не используется.

Результат — `test-results/p4-edge.json` и скриншоты `p4-player-desktop.png`/`p4-player-narrow.png`. Подробные измеренные значения, исправления и ограничения — в [P4](verification/P4.md). Системный выход браузера приглушён: PCM/live-проверки не являются прослушиванием физических динамиков или измерением аппаратной задержки.

Для повторения модульного снимка P4 без тестов будущих этапов:

```powershell
npm.cmd run test:unit -- tests/music.test.ts tests/training.test.ts tests/results.test.ts tests/audio-plan.test.ts --reporter=json --outputFile=test-results/p4-unit.json
```

## Воспроизведение P1

После [подготовки зависимостей](DEVELOPMENT.md) из корня репозитория:

```powershell
npm.cmd --prefix experiments/p1 run check
npm.cmd --prefix experiments/p1 run build
npm.cmd --prefix experiments/p1 test
```

Сборка должна быть свежей: тесты запускают статический сервер собранного `dist`, а не dev-server. Порт 4173 перед запуском свободен. Тест сам создаёт и завершает локальный сервер; отдельно запускать его не требуется.

Для текущего набора нужен установленный Microsoft Edge в стандартном расположении Windows. Проверка реальной видимости также принимает путь к исполняемому файлу через `BASS_P1_EDGE_PATH`. Используются изолированные временные профили; повседневный профиль браузера и пользовательские данные не затрагиваются.

Результат команды — именованные сценарии, ненулевой код возврата при ошибке и JSON в `experiments/p1/results/edge-windows.json`. Этот каталог игнорируется Git. Зафиксированный результат этапа хранится отдельно в [verification/P1_EDGE_WINDOWS.json](verification/P1_EDGE_WINDOWS.json); обновлять его осознанно вместе с отчётом после успешного прогона.

## Состав проверок отдельного стенда P1

| Область | Что действительно проверяется |
| --- | --- |
| Запуск | Production-сборка на постоянном origin, пустой/отключённый сетевой кеш, запрет внешних HTTP-запросов при доступном loopback. Отдельный внешний запрос подтверждает работу запрета. |
| Порт | Второй сервер получает `EADDRINUSE`; первый продолжает отвечать, origin не меняется. |
| Звук | Пользовательский старт, два отсчётных события, последовательность шагов цикла, интервалы запланированных событий и наличие сигнала в анализаторе Web Audio. |
| Управление | Пауза сохраняет позицию и выключает сигнал; продолжение не повторяет отсчёт; смена BPM применяется к следующей ещё не отправленной четверти. |
| Видимость | Отдельный Edge подключён через CDP с `noDefaults:true`; переключение настоящей вкладки вызывает `document.hidden`, паузу и тишину. Возврат не возобновляет звук без команды. |
| Остановка | Отменены события, освобождён голос, после остановки нет сигнала и новых событий; три новых старта не удваивают расписание. |
| PCM | Настоящий `OfflineAudioContext`: шесть звуковых начал с заданными интервалами, сменой темпа и циклом; проверяются амплитуда и нулевой RMS после остановки. |
| Данные | Запись/чтение/экспорт; отказ повреждённого JSON, новой версии, неверного BPM и нарушенной ссылки до изменения данных. |
| Транзакции | Отмена без подтверждения; принудительный abort после успешного `put` с проверкой сохранения всего исходного снимка. |
| Восстановление | Полный перезапуск браузера с тем же профилем; импорт в чистый профиль; полная замена с удалением старых записей. |

Обычный запуск Playwright эмулирует фокус; он оказался непригоден для доказательства скрытия вкладки. Поэтому этот сценарий использует отдельный процесс Edge без стандартных CDP-переопределений, polling по таймеру и настоящее переключение вкладки. Подмены свойства `document.hidden` или искусственного события `visibilitychange` нет.

## Пределы результатов

- Запрет внешних запросов моделирует отсутствие интернета с доступным localhost. Сетевые адаптеры Windows не отключались.
- Системный звуковой вывод тестового браузера приглушён. Анализируются сигнал внутри Web Audio и PCM; динамики, удобство тембра, физическая задержка и игра реального баса не измерялись.
- Проверены Edge 157.0.4341.42 и конкретная Windows-среда. Chrome, Firefox, телефон, сон компьютера, смена аудиоустройства и длительные занятия не испытаны.
- Проверены однократная схема данных версии 1 и отказ неизвестной версии. Реальных миграций, переполнения диска/квоты, обновления продуктовой схемы и нескольких одновременно пишущих вкладок пока нет.
- Продуктовая синхронизация звука с грифом, немые такты, подразделения и лестница темпа проверены на P4. Полный цикл с историей и восстановлением остаётся P5/P6; музыкальный и экранный материал P2/P3 имеет отдельные отчёты.

## Правила добавления проверок

Использовать R-014 как источник контрольных значений музыкальной модели. Для генератора проверять множество допустимых ответов и невозможные фильтры. Для проигрывателя проверять данные расписания отдельно от аудиосигнала и отображения. Для хранения — транзакции и переносимое восстановление. Для интерфейса — действия с клавиатуры и понятность результата.

Не переносить статус «пройдено» со стенда на соответствующее продуктовое требование целиком. Новая проверка должна подтверждать наблюдаемое поведение или риск, а не повторять формулу реализации в ожидаемом значении.
