## Приложение: установка и запуск

Команды из корня репозитория в PowerShell:

```powershell
npm.cmd ci --no-fund --no-audit
npm.cmd run build
npm.cmd start
```

Открыть [http://localhost:4173](http://localhost:4173). Сервер слушает loopback и раздаёт только корневой `dist`; при занятом порте останавливается без смены origin. Для остановки нажать Ctrl+C. После первичной установки и сборки внешние ресурсы не нужны; для запуска выбранного сервера остаётся необходим Node.js.

`npm ci` вызывает postinstall, а `npm run build`/`npm run dev` — prebuild/predev подготовки локальной alphaTab **1.9.0**. `scripts/prepare-music-bank.mjs` проверяет точный исходный хеш/версию и создаёт ignored `public/vendor/music-bank` со своими ESM `.js`, worker/worklet, шрифтом, soundfont и лицензиями. Явная команда подготовки после изменения собственного patch/helper — `node scripts/prepare-music-bank.mjs`; generated-файлы вручную не редактируются. Продукт не загружает ресурсы с CDN и не импортирует `experiments`.

Для редактирования с обновлением страницы: `npm.cmd run dev`. Он использует тот же порт: production-сервер и dev-server нельзя запускать одновременно. Этот режим предназначен для разработки, а воспроизводимая браузерная проверка использует production-сборку.

Проверки приложения: `npm.cmd run check`, `npm.cmd test` и 12 браузерных runners из [TESTING](TESTING.md), включая `npm.cmd run test:design`. Перед браузерными проверками выполнить build. По умолчанию runner требует свободный 4173 и сам владеет сервером; уже работающий пользовательский процесс нельзя завершать автоматически. Все 12 продуктовых runners допускают только явный `--reuse-server` после побайтного сравнения GET 200 `/` с текущим `dist/index.html`; reused-сервер отмечается `owned:false` и не закрывается/перезапускается. Дополнительные fixture-порты: 4181 audio, 4182 storage, 4183 release, 4185 ear, 4187 harmony. Команды выполнять последовательно. `npm.cmd run docs:check` проверяет документацию; детали — в TESTING.

После подготовки можно запускать `start.cmd` двойным щелчком либо `.\start.cmd` из PowerShell. Launcher переходит в каталог проекта, проверяет Node.js/наличие `dist` и запускает тот же сервер; первичную установку/сборку он не выполняет. Открыть адрес в Edge вручную, оставить окно сервера работающим, завершить Ctrl+C. Реальный запуск проверен HTTP 200 на `localhost:4173` с чистым выводом CMD. Технические сообщения launcher — ASCII/английские для совместимости кодировки консоли; интерфейс приложения русский. Это не установщик Node.js или проверка перезагрузки Windows.

## Работа с версией 1.4.0

«Изучение» показывает карту и связи. «Задания» запускает отдельную серию из шести типов, по умолчанию десять вопросов. «Найди ноту» допускает разные октавы, «Найди высоту» — только указанную (например, A1). «Найди ступень» использует выбранную структуру, «Найди интервал» — все ноты области и явный интервал от тоники. Подсказка, пропуск и исправление имеют разные результаты. При изменении области или режима старая серия закрывается; для продолжения нужен новый старт.

«Последовательности» показывает маршрут и плеер: темп, длительность, отсчёт, фрагмент, один проход/цикл/лестницу, метроном и раздельную громкость. Структурные параметры редактируются до старта или после стопа; при обычном повторе можно менять BPM во время игры. Нажать «Старт» для разрешения звука браузером. Space управляет стартом/паузой/продолжением, Escape останавливает; в интерактивных полях сокращения не перехватываются. Скрытие вкладки ставит практику на паузу до явного продолжения.

Раздел «Слух» предлагает тонику/мажорное или минорное трезвучие, 1–20 вопросов и темп 60–120 BPM. «Прослушать» играет тонику, паузу и цель; кнопки 1/3/5 открываются после конца. Повтор звука, показ ответа и пропуск имеют разные результаты. Остановленный/скрывшийся cue нужно прослушать заново целиком; перезагрузка не запускает звук автоматически.

«Маршрут занятия» задаёт 3 минуты грифа, 3 слуха и 4 практики. «Начать маршрут» открывает первый блок и глобальную панель. Пауза/скрытие останавливают активный счёт; продолжение и переход явные. Ранний переход/стоп оставляют фактическое время. Статистика маршрута — время таймера, не оценка игры/внимания.

«Аккомпанемент» играет C–F–G–C в 4/4, бас 1–3–5–3, аккордовую гармонию и клик. Выбрать 40–220 BPM, отсчёт/повтор, нажать «Старт». Выключить бас в микшере, чтобы играть свою партию; громкости и mute доступны на ходу. Темп/отсчёт/повтор меняются после «Стоп». Дробная пауза/продолжение сохраняют место без нового отсчёта; hidden требует явного продолжения, уход из раздела останавливает звук. Space/Escape действуют с теми же guards полей/кнопок. Позиции предпросмотра — примеры звучащих нот, не подбор лучшей аппликатуры.

Настройки и каждое фактическое действие экранной серии автоматически сохраняются в базе `bass-study` этого профиля на `http://localhost:4173`; спокойный статус виден внизу навигации, ошибка — в отдельном баннере. «Сохранение…» ещё не означает завершённую запись: перед закрытием дождаться подтверждения. При ошибке доступно «Повторить сохранение»; экспорт содержит подтверждённые данные. Перезагрузка сохраняет историю попыток, но не продолжает старый квиз/таймер: новое занятие получает отдельную запись. Если база не открылась при запуске, интерфейс прямо сообщает о временной памяти страницы — до её закрытия нужно скачать копию.

Одна вкладка владеет правом записи. Во второй контролы заблокированы с сообщением; закрыть первую и нажать «Проверить снова», чтобы загрузить свежие настройки. Это не совместное редактирование. Если браузер не предоставляет Web Locks, приложение объясняет требование поддерживаемого Edge.

Раздел «Мои занятия и настройки» различает экранные задания, ручные отметки, слух и маршруты; фильтр/сводки сохраняют источники отдельно. Пресеты содержат также раздел/настройки слуха и сопровождения. У незавершённого слухового вопроса цель скрыта в деталях. Ручная форма хранит комфортный BPM/заметку и время эталона без отсчёта/пауз; это не измерение реальной игры. При начале ввода фиксируются материал и время; смена раздела/запуска не переносит старую заметку на новый материал. Для переноса есть явное действие формы, для обновления времени — отдельная кнопка.

«Экспортировать JSON» скачивает компактный снимок схемы **7**. Принимаются версии 1–7 до **64 МиБ UTF-8**, включая прежние форматированные копии. Preview ничего не меняет, подтверждение полностью заменяет данные одной транзакцией; текущую копию можно экспортировать заранее. Базы 1–6 обновляются автоматически; ошибка старой записи отменяет upgrade без сброса. Переход 6→7 сохраняет профиль/введение/черновики и исходные события/даты без повторной инициализации. Размер файла не гарантирует RAM/квоту; большой импорт и первое полное чтение могут задерживать страницу.

Адаптер `readSnapshot()` использует подтверждённый замороженный кеш под единственным writer lease; `readSnapshot({fresh:true})` предназначен для явного чтения внешних изменений. Обычные записи обновляют кеш после commit. История строит тело при открытии; это не альтернативный источник постоянных данных. Подробный контракт — в архитектуре.

Браузер может очистить локальные данные. Копии хранить вне профиля браузера; GitHub не содержит историю занятий. `localhost`, `127.0.0.1` и другие порты дают разные области данных. Проигранный эталон не получает автоматическую оценку исполнения на инструменте.

## Отдельный стенд P1: первичная подготовка

```powershell
npm.cmd --prefix experiments/p1 ci --no-fund --no-audit
npm.cmd --prefix experiments/p1 run build
```

Первичная установка требует доступа к npm registry. Сборка включает проверку TypeScript и создаёт игнорируемую Git папку `experiments/p1/dist`. Исходные файлы, lockfile и все необходимые ресурсы остаются локально; стенд не обращается к CDN.

## Стенд P1: запуск

```powershell
node experiments/p1/server.mjs
```

Открыть [http://localhost:4173](http://localhost:4173). Остановить сервер сочетанием Ctrl+C в его терминале. Сервер раздаёт только содержимое `dist` и слушает loopback `127.0.0.1`; этот локальный процесс должен оставаться запущенным. Наличие Node.js требуется и после сборки для выбранного способа запуска.

При занятом порте процесс завершается с `EADDRINUSE`, без выбора другого порта. Не менять `localhost` на `127.0.0.1` и не выбирать случайный порт для обычных занятий: это другой origin и другое браузерное хранилище. Переменная `BASS_P1_PORT` существует для эксперимента; автоматические проверки используют именно 4173.

## Стенд P1: возможности

- Эталонные синтезированные ноты, отсчёт, цикл, ручная смена темпа, пауза и остановка.
- Синтетические настройки, два пресета и два результата разного происхождения; отдельная IndexedDB-база `bass-study-p1-storage`.
- Экспорт в текстовое поле, предварительная проверка и подтверждаемая полная замена тестовых данных.
- Диагностика состояния звука. Это техническая информация стенда, которую не требуется переносить в пользовательский интерфейс тренажёра.

Проба использует короткий двухдольный отсчёт и ускоренный темп для автоматических проверок; продуктовые значения определены требованиями. Музыкальный гриф, полноценные квизы, немые такты и лестница темпа здесь ещё не реализованы. Формат синтетических записей не является утверждённой полной схемой будущего продукта.

## Нотация, личные файлы и вход версии 1.3.0

В «Последовательностях» ноты и четырёхлинейный TAB относятся к уже выбранному маршруту и длительности. Басовая запись на октаву выше звучания; TAB сохраняет настоящую струну/лад. Рендерер появляется лениво, внешний CDN не нужен. MIT/OFL уведомления находятся в `public/licenses` и попадают в `dist`.

В «Аудиодорожках» выбрать один WAV/MP3 или до четырёх подготовленных stems с общим началом. Указать A/B в секундах, повтор и скорость; диапазон [A,B), скорость 0.5–1.5 меняет и высоту. Во время проигрывания доступны mix/seek, изменение A/B/rate/loop требует паузы. Меньший файл заканчивается тишиной до общего B. После reload/restore выбрать исходники снова: JSON хранит только метаданные и SHA-256. Имена могут отличаться; несовпадающее содержимое не принимается. Ошибка/отмена сохраняют предыдущий набор. Пределы исходников/расчётного PCM и память — в [R-019](REQUIREMENTS.md#r-019).

В «Аудиовходе» выбрать устройство и явно нажать «Подключить». Список устройств не запрашивает запись. Вход не выводится на динамики; для собственного прослушивания использовать direct monitoring интерфейса. Показаны уровень, неопределённость/приблизительная высота и запрошенные/фактические параметры. Выход/hidden/stop останавливают capture; новое подключение только по кнопке. При восстановлении сохраняется выбор deviceId, разрешение и запись не запускаются. Это диагностический режим, без оценки игры. Реальный бас/USB/задержка требуют [отдельного протокола](verification/P7-04-06.md#протокол-следующего-испытания-с-настоящим-басом).

Vite предупреждает о крупных main/notation chunks; сборка успешна, notation загружается лениво. Первичная установка зависимостей нужна отдельно; отсутствие внешних запросов относится к построенной поставке, не npm install. Итоговая проверка lockfile включала `npm.cmd ci --dry-run --ignore-scripts --no-audit --no-fund` и `npm.cmd ls --depth=0`; новая установка clean-ci на занятом стенде не выдаётся за выполненную.

## Возможности 1.4.0 и локальные черновики

В текущей оболочке [P9](#общая-оболочка-и-vis-01-r5-результат-p9) доступны «Введение» и бинарный выбор «Светлая / Тёмная». Тема хранится в глобальном профиле отдельно от пресетов; её смена не прерывает звук. Старый `system` остаётся совместимым профилем/импортом и показывает разрешённую тему до явного выбора пользователя. Введение необязательно и повторно доступно; миграция старой базы сохраняет прежний музыкальный материал.

Учебная форма остаётся полной, а окно показа грифа задаётся независимо, исходно 0–12. Смена тоники/структуры/формы и ручная правка границ не сокращают материал формы; ручная смена струн включает свободный режим. На каждой части грифа четыре строки G–D–A–E, неиспользуемая струна остаётся пустой; названия струн буквенные. Свободный диапазон сохраняет открытые струны. Обычные задания и последовательности используют точные позиции формы, задания на произвольный интервал — хроматический прямоугольник самой формы. Невалидный диапазон убирает карту до исправления и не допускает старый контекст к новому заданию. Номера пальцев включаются отдельно от ступеней и сохраняются вместе с настройками упражнения. Подробный контракт — [R-023/P9](REQUIREMENTS.md#r-023-p9).

Черновики возникают при воспроизведении эталона или вводе заметки. Текст сохраняется с задержкой 300 мс, время — контрольное сохранение каждые 5 с и на остановке/смене материала. После перезапуска черновики доступны в истории, но не считаются результатами до «Сохранить ручную отметку». Save учитывает только ещё не перенесённое время. Материал и локальный день разделяют черновики; старый можно открыть, сохранить или удалить с подтверждением. Аварийное завершение не гарантирует последний незавершённый checkpoint. Экспорт ждёт ожидающие изменения; резервная копия остаётся полезной при отказе браузерного хранения.

В последовательностях исходно показан гриф; «Ноты и TAB» открывает ту же последовательность с выделенным включительным фрагментом. Стрелки/Home/End работают внутри записи, Enter/Space явно переходят к позиции грифа; кнопка возврата восстанавливает выбранную ноту. Курсор и текущие такт/доля/повтор принадлежат существующему плееру. Дорожки показывают сотые секунды; «Начало здесь / Конец здесь» фиксируют текущую позицию после паузы без автоматического продолжения. Локальные аудиофайлы по-прежнему нужно выбирать после reload/restore.

## Общая оболочка и VIS-01 r5: результат P9

Утверждённые [VIS-01-A3 r5](design/screens/01-fretboard.md) и общая оболочка реализованы в рабочей копии по [D-030](DECISIONS.md#d-030) и [R-023/P9](REQUIREMENTS.md#r-023-p9). [P9-10–12](PLAN.md#p9) выполнены в проверенном объёме: типы/build, 360/360 unit в 21 файле и 222/222 браузерных сценария в 12 runners. Доказательства и ограничения — в [P9](verification/P9.md). Сохранённые HTML/снимки r5 остаются неизменным визуальным ориентиром; историческая приёмка 1.4.0 не переписывается, новый выпуск/commit/push не объявлены.

В левой навигации доступны прежние разделы, «Мои занятия», введение и два выбора темы. «Мои занятия» открывает настоящую панель истории; навигация или её summary закрывают панель. Закрытая история не строит карточки после каждого ответа. Текущий спокойный статус сохранения находится внизу меню; ошибки записи и временная память показываются отдельным баннером. Данные, звуковая координация и самостоятельность заданий сохраняют прежние контракты; остальные экраны функционально не переработаны.

На экране грифа панель параметров сворачивается. Тоника, структура и форма используют видимый picker поверх прежнего select. Пальцы включаются отдельным switch и сохраняются в материале; октавные участки, интервал и состояние панели живут только в текущей странице. Формы подписаны «Форма A · 5–8», компактные — «Тоника C · лад 8 · E»; пояснение каталога остаётся отдельно. Весь выбранный диапазон, исходно 0–12, и четыре струны сохраняются, при нехватке ширины гриф переносится на подписанные части с маркерами 46 px / текстом 18 px. Форма не подменяется окном показа. Кнопка «Показать форму целиком» явно расширяет область; смена тоники/структуры/формы сама её не меняет.

Старая схема 6, профили `system` и сохранённые диапазоны читаются без неявной перезаписи. В бинарном UI старый `system` показывает фактическую тему, пока пользователь явно не выберет светлую/тёмную. Введение сохраняет валидный вид и расширяет его для учебного трезвучия. Явный старт маршрута исправляет невалидный вид своим материалом. В нотах стрелки меняют фокус, а «Показать на грифе» при необходимости расширяет область до выбранной ноты; прежняя форма и точная последовательность сохраняются.

Основные файлы: [чистая группировка октав](../src/music/octaves.ts), [SVG грифа](../src/ui/fretboard.ts), [выбранная нота и связи](../src/ui/study-details.ts), [picker](../src/ui/select-picker.ts), [координатор](../src/main.ts). Новых зависимостей для переноса нет. `npm.cmd run test:design` запускает продуктовые сценарии P9, результат — `test-results/p9-design-edge.json`. После актуального build выполнен `npm.cmd run test:design -- --reuse-server`: 7/7 сценариев, включая 20 сочетаний темы/ширины/диапазона. Все 12 runners прошли с подтверждённым чужим сервером (`owned:false`) без его shutdown/restart; правила и команды — в [TESTING](TESTING.md), итог — [P9](verification/P9.md). Следующие референсы/полная переработка других экранов не запускаются автоматически.

## «Табулатура и ноты»: «Студия» P10-01

Пользователь утвердил A «Студия» и поручил перенос в основное приложение, затем уточнил название **«Табулатура и ноты»**. Внутренние ID `tracks`, поле `musicBank` и схема 7 остаются прежними. Вкладка **«Партитуры»** использует верхний транспорт, прокручиваемое нотное поле и правый микшер; **«Аудиозаписи»** сохраняет прежний проигрыватель WAV/MP3 и его наборы. B и панель сравнения A/B остаются только в референсе.

В «Партитурах» открыть один файл или выбрать папку. Каталог создаётся только в памяти, ищет по имени/пути и показывает по **80** файлов на страницу. Байты/структура/хеш читаются у выбранной песни. У каждого инструмента отдельно настраиваются «Показывать», «Звучит», solo и громкость; действия не привязаны к басу. «Ноты» и «TAB» включаются независимо; скрытие обоих не отключает звук. При отсутствии струнного TAB показывается объяснение. Смена скорости синтеза меняет темп; varispeed старых «Аудиозаписей» по-прежнему меняет и высоту.

После reload/restore каталог и исходники отсутствуют до нового выбора. Сохранённая песня требует совпадения размера/SHA-256; другое имя при тех же байтах допустимо. JSON схемы 7 хранит только дескриптор выбранной партитуры и настройки микшера/представления/фрагмента. `File`, весь каталог, PCM, байты, текущее время и состояние «играет» не сохраняются. Логический предел исходного файла — **64 МиБ**; это не обещание пиковой памяти декодера/парсера или доступной RAM. Остальные точные пределы — [R-024/P10](REQUIREMENTS.md#r-024-p10).

Один активный звуковой владелец координируется в main. При скрытии вкладки воспроизведение приостанавливается до явного продолжения; уход/restore/retiring отменяют pending file/engine intent. Собственной истории ручных результатов и автоматической оценки игры у музбанка нет. Основные файлы — [модель](../src/music-bank/model.ts), [каталог](../src/music-bank/catalog.ts), [ленивый загрузчик](../src/music-bank/engine.ts), [UI](../src/ui/music-bank.ts), [подготовка ресурсов](../scripts/prepare-music-bank.mjs).

После build фактически выполнены `node tests/music-bank-channels.mjs`, `node tests/music-bank-storage-browser.mjs --reuse-server` и `node tests/music-bank-browser.mjs --reuse-server`. Они проверяют продуктовую поставку, настоящий DSP/живой выход, UI/каталог и native schema7; итоги и сохранённые ограничения — в [P10](verification/P10.md). Исторические P8/P9/P10-00/r1 не переименовываются в новую приёмку.
