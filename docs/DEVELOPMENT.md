# Разработка bass_study

Установка, запуск, структура каталогов, команды и проверки. Устройство приложения — в [архитектуре](ARCHITECTURE.md), правила работы — в [AGENTS](../AGENTS.md).

## Среда

- Windows и Microsoft Edge в стандартном расположении (`Program Files (x86)\Microsoft\Edge\Application\msedge.exe`): браузерные проверки запускают Edge через Playwright (`channel: 'msedge'`).
- Node.js `^22.12.0 || ^24.0.0 || >=26.0.0` (поле `engines` в `package.json`), npm из `packageManager`. CI использует Node 24.
- Сеть нужна только для `npm ci`. Собранное приложение и проверки работают без внешних запросов.
- Если политика выполнения PowerShell блокирует `npm.ps1`, вызывай `npm.cmd`.

## Установка и запуск

```powershell
npm ci
npm run build
npm start
```

Открыть [http://localhost:4173](http://localhost:4173) в Edge; остановка — Ctrl+C. Сервер слушает только `127.0.0.1:4173` и при занятом порте завершается, не выбирая другой: другой адрес — другой origin и другая база IndexedDB. После сборки приложение можно запускать `start.cmd`: он проверяет Node.js и `dist/index.html` и запускает тот же сервер, но не устанавливает зависимости и не собирает.

`npm ci` (через `postinstall`), `npm run build` и `npm run dev` (через `prebuild`/`predev`) сначала выполняют `scripts/prepare-music-bank.mjs`: он готовит локальный вендор alphaTab в `public/vendor/music-bank` ([подробности](ARCHITECTURE.md#build)). После правки `scripts/music-bank/*` вендор пересобирается командой `npm run prepare:music-bank`. Сгенерированные файлы вручную не правятся.

`npm run dev` — Vite с обновлением страницы на том же `127.0.0.1:4173` (`--strictPort`), поэтому одновременно с `npm start` он не запускается. Браузерные проверки используют production-сборку, а не dev-сервер.

## Регрессия: быстрый и полный набор

`npm run test:regression` выполняет быстрый набор, `npm run test:full` (то же, что `npm run test:regression -- --full` или `BASS_FULL=1`) — полный. Оба записывают протокол в `test-results/regression-<id>/`:

1. `docs` — `scripts/check-docs.mjs`.
2. `types` — `tsc --noEmit`.
3. `build` — копирует `public` без вендора, заново готовит вендор alphaTab и собирает приложение в каталог прогона, не трогая `dist` и `public` рабочей копии.
4. `unit` — Vitest с JSON-отчётом.
5. `vendor` — `node --test scripts/music-bank/vendor.test.mjs`.
6. `dsp` — `tests/music-bank-channels.mjs` на синтетических партитурах.
7. Браузерные раннеры из [списка](#runners): сначала `input` в одиночку, затем остальные параллельным пулом; при `--corpus` в тот же пул добавляются `dsp-corpus` и `music-bank-corpus` на личной коллекции.
8. `provenance` — входные файлы и сборка не изменились за время прогона.

Шаги 1–6 идут последовательно. В пуле одновременно работают до `--jobs=<N>` раннеров (или `BASS_TEST_JOBS`, от 1 до 8); по умолчанию — 3, но не больше числа логических процессоров минус два. Долгие раннеры стартуют первыми. `input` анализирует захват fake-устройства в реальном времени и при процессоре, занятом другими экземплярами Edge, классифицирует сигнал иначе, поэтому идёт отдельно. При четырёх раннерах одновременно на машине с четырьмя ядрами начинали падать и live-сценарии звука; если такое повторяется, уменьши `--jobs`. Вывод раннеров в консоли помечен именем шага, полный вывод каждого — в `logs/<шаг>.log`.

**Состав наборов.** Полный набор выполняет все сценарии; его время не ограничено. Быстрый набор рассчитан не более чем на пять минут на рабочей машине и пропускает сценарии, помеченные в раннере `markFullOnly` (`tests/helpers/browser-case.mjs`). Причина задаётся константой `FULL_ONLY`:

- `hiddenTab` — настоящее скрытие вкладки в отдельном процессе Edge через CDP;
- `viewports` — дополнительные размеры окна визуальных матриц; типичный размер 1366 (1366×768) в обеих темах остаётся в быстром наборе отдельным сценарием;
- `liveAudio` — live-сигнал `AudioContext` в реальном времени: под нагрузкой параллельного пула он нестабилен, а PCM и интерфейс раздела остаются в быстром наборе. Состояние `running` в интерфейсе не означает, что аудиочасы уже идут: headless Edge запускает устройство вывода с задержкой, и `currentTime` может стоять 0,4–0,6 с. Сценарий, который проверяет время практики, отмеряет интервалы по аудиочасам (`untilAudio` из `tests/rhythm/browser-context.mjs`), а не задержками Node;
- `separateProcess` — отдельный процесс Edge со своим профилем (нативная IndexedDB вне fixture-контекста, перезапуск браузера);
- `unstable` — сценарии, нестабильные в RDP и под нагрузкой;
- `smoke` — дымовой отбор. В быстром наборе каждого раннера остаются сценарии, которые покрывают разные основные потоки раздела: загрузку, базовое действие, сохранение и восстановление, ошибку; более подробные варианты тех же потоков идут в полный набор. Отбор ориентируется на время прогона, а не на число сценариев.

Новый сценарий по умолчанию входит в быстрый набор. Если быстрый набор перестаёт укладываться во время, дорогой сценарий переводится в полный набор с причиной, а не удаляется. Пропущенный сценарий не исчезает: он записывается в отчёт раннера со статусом `skipped` и причиной, а в `summary.json` — в `skippedChecks` шага и в счётчик `browser.skipped`. В полном наборе пропусков быть не должно, иначе шаг не проходит.

**Изоляция при параллельном запуске.** В регрессии каждый раннер поднимает свой сервер сборки и свой fixture-сервер на порте, выданном ОС (порт 0); `4173` и постоянные порты fixtures не используются. Профили Edge создаются во временных каталогах `mkdtemp`, отчёты и снимки экрана имеют разные имена. Перезапуск сервера в `release` занимает тот же выданный ему порт, чтобы сохранить origin.

В режиме регрессии раннеры поднимают свои серверы и fixtures на свободных портах, не используют `4173` и отказываются от `--reuse-server`, поэтому запущенное приложение пользователя не мешает и не затрагивается. Каждый отчёт сверяется с идентификатором прогона, профилем и набором (`mode`: `fast` или `full`); шаг проходит, только если все выполняемые сценарии прошли, а пропущены лишь сценарии полного набора с причиной.

| Файл | Содержимое |
| --- | --- |
| `summary.json` | Статус, набор и число параллельных раннеров, шаги с началом и длительностью, пропущенные сценарии, коммит, признак грязной рабочей копии, версии Node и Edge, хеши входов и сборки |
| `inputs.json`, `build.json` | Хеши входных файлов (отслеживаемых и неигнорируемых) и файлов сборки |
| `reports/`, `logs/` | JSON-отчёты шагов и полный вывод каждого шага |

### Личная коллекция: `--corpus`

```powershell
$env:BASS_MUSIC_BANK_ROOT = '<папка с партитурами>'
npm run test:regression -- --corpus
```

`BASS_MUSIC_BANK_ROOT` должен указывать на папку с партитурами. Выборка задаётся манифестом с относительными путями, размерами и SHA-256 файлов (его загружает `tests/helpers/music-bank-fixtures.mjs`); несовпадение байтов останавливает проверку. Без `--corpus` используются синтетические партитуры, которые создаются в каталоге результатов. Отдельно тот же режим включается флагом `--corpus` у `node tests/music-bank-channels.mjs` и `node tests/music-bank-browser.mjs`.

### Отдельный запуск

- Раннер проверяет текущий `dist`: сначала `npm run build`.
- По умолчанию раннер сам поднимает сервер на `localhost:4173`, поэтому порт должен быть свободен. Если там уже работает это же приложение, добавь `-- --reuse-server`: раннер выполнит только чтение `GET /`, сравнит ответ побайтно с `dist/index.html` и отметит сервер как чужой (`owned: false`). Чужой сервер не останавливается и не перезапускается.
- Отдельно запущенный раннер выполняет быстрый набор; `-- --full` (или `BASS_FULL=1`) включает сценарии полного набора.
- Fixtures слушают свои порты на `127.0.0.1`: 4181 audio, 4182 storage, 4183 release, 4185 ear, 4192 input, 4193 tracks (также rhythm и оба music-bank), 4194 notation (также uiux и design). Раннеры с общим портом нельзя запускать параллельно; надёжнее запускать раннеры по одному. Параллельный запуск — только через `test:regression`/`test:full`, где порты выдаёт ОС.
- `test:rhythm`, `test:music-bank` и `test:p13` принимают `-- --case=<часть имени сценария>`; пустой или ничего не нашедший выбор завершается ошибкой.
- Отчёт — JSON в `test-results/`; при ошибке код возврата ненулевой.
- Для сценариев настоящего скрытия вкладки нестандартный путь к Edge задаётся переменными `BASS_P4_EDGE_PATH`, `BASS_EAR_EDGE_PATH`, `BASS_INPUT_EDGE_PATH`, `BASS_TRACKS_EDGE_PATH`, `BASS_P13_EDGE_PATH`.

## CI

`.github/workflows/regression.yml` запускается на pull request и push в `main`: `windows-2025`, Node 24, `npm ci`, установка Edge при его отсутствии, полный набор `npm run test:full` без `--corpus`, раннеры последовательно (`BASS_TEST_JOBS=1`): параллельный холодный старт отдельных процессов Edge на раннере GitHub не укладывается в таймаут первой навигации. Протокол прогона (`summary.json`, `inputs.json`, `build.json`, отчёты и логи) сохраняется артефактом `portable-regression`.

## Правила проверок

- **Музыка.** Контрольные значения берутся из независимых примеров [R-014](REQUIREMENTS.md#r-014), а не повторяют формулу реализации. Для генератора проверяется множество допустимых ответов и невозможные фильтры.
- **Задания.** Проверяются через видимую формулировку и действия пользователя. Самостоятельный первый ответ проверяется отдельно от исправления, показа и пропуска; также дубли в «найди все», исходный контекст результата и отмена серии при смене параметров. Недопустимый диапазон не должен молча использовать старый контекст.
- **Звук.** План, live-сигнал, PCM и интерфейс проверяются отдельно. Запланированное событие — не прозвучавшее: отменённые исключаются, время сравнивается с часами `AudioContext`. После дробной паузы проверяется непрерывность сетки; конечный проход завершается по `finishAt`. Настоящее скрытие вкладки проверяется в отдельном процессе Edge через CDP (`noDefaults: true`) без эмуляции фокуса и подмены `document.hidden`.
- **Данные.** Используется нативная IndexedDB, память её не подменяет. Откат проверяется отказом после уже успешного `put`; квота — через CDP `Storage.overrideQuotaForOrigin`, без заполнения диска. Кеш проверяется отдельно от свежего чтения и от независимого чтения IndexedDB. Импорт до подтверждения не меняет базу и занятие.
- **Без тестового API в продукте.** Наблюдение и управление (`window.p4`, `window.p5` и подобные) есть только в fixtures; правильные ответы не появляются в DOM и ARIA приложения.
- **Изоляция.** Раннеры используют временные профили, отключают кеш и блокируют внешние HTTP-запросы страниц. Раннеры со звуком запускают Edge с `--mute-audio`.
- **Пределы доказательств.** PCM, live-сигнал и fake-устройство не подтверждают физические динамики, тембр, настоящий бас, USB-интерфейс и сквозную задержку. Контраст по computed styles — выборочная проверка, а не сертификация WCAG. Проверены только Windows и Edge.
- **Результаты.** Отчёты остаются в `test-results/` и артефактах CI; в репозиторий их не коммитят.
