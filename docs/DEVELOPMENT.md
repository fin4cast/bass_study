# Подготовка и запуск bass_study

Актуально на 2026-11-08. Приложение **1.2.0** содержит базовый MVP, улучшения данных, слух/маршрут и принятое на [P7-03](verification/P7-03.md) сопровождение C–F–G–C. База/копия — схема 4 с миграциями 1/2/3. Исторические стенды P1/scale не заменяют продукт; прототипы нотации/файлов/входа ещё не прошли приёмку.

## Приложение: установка и запуск

Команды из корня репозитория в PowerShell:

```powershell
npm.cmd ci --no-fund --no-audit
npm.cmd run build
npm.cmd start
```

Открыть [http://localhost:4173](http://localhost:4173). Сервер слушает loopback и раздаёт только корневой `dist`; при занятом порте останавливается без смены origin. Для остановки нажать Ctrl+C. После первичной установки и сборки внешние ресурсы не нужны; для запуска выбранного сервера остаётся необходим Node.js.

Для редактирования с обновлением страницы: `npm.cmd run dev`. Он использует тот же порт: production-сервер и dev-server нельзя запускать одновременно. Этот режим предназначен для разработки, а воспроизводимая браузерная проверка использует production-сборку.

Проверки приложения: `npm.cmd run check`, `npm.cmd test`, `npm.cmd run test:browser`, `npm.cmd run test:training`, `npm.cmd run test:audio`, `npm.cmd run test:storage`, `npm.cmd run test:release`, `npm.cmd run test:ear`, `npm.cmd run test:harmony`. Перед ними выполнить build. По умолчанию runner требует свободный 4173 и сам владеет сервером; уже работающий пользовательский процесс нельзя завершать автоматически. У harmony/ear/storage/release есть явный `--reuse-server` с проверкой текущего built index и запретом shutdown/restart чужого сервера. Дополнительные fixture-порты: 4181 audio, 4182 storage, 4183 release, 4185 ear, 4187 harmony. Команды выполнять последовательно. `npm.cmd run docs:check` проверяет документацию; детали — в [TESTING](TESTING.md).

После подготовки можно запускать `start.cmd` двойным щелчком либо `.\start.cmd` из PowerShell. Launcher переходит в каталог проекта, проверяет Node.js/наличие `dist` и запускает тот же сервер; первичную установку/сборку он не выполняет. Открыть адрес в Edge вручную, оставить окно сервера работающим, завершить Ctrl+C. Реальный запуск проверен HTTP 200 на `localhost:4173` с чистым выводом CMD. Технические сообщения launcher — ASCII/английские для совместимости кодировки консоли; интерфейс приложения русский. Это не установщик Node.js или проверка перезагрузки Windows.

## Структура приложения

- `src/music/index.ts` — чистые расчёты и типы музыкального материала.
- `src/training/index.ts` и `src/training/results.ts` — чистые вопросы, сессии, оценка, маршруты и раздельные модели результатов.
- `src/main.ts` — общие настройки и исследовательский SVG; `src/ui/training.ts` — экранные задания и последовательности. У каждого вида интерфейса своё оформление.
- `src/audio/plan.ts` — чистая музыкальная сетка; `src/audio/engine.ts` — Tone.js/Web Audio; `src/ui/player.ts` — пользовательский плеер и реакция на скрытие вкладки.
- `src/storage/model.ts` — типы/строгая валидация, `src/storage/index.ts` — нативный IndexedDB, `src/storage/memory.ts` — временное хранилище; `src/app/write-queue.ts` — очередь записей с явным повтором ошибок.
- `src/ui/history.ts` — реальные история/пресеты, ручная отметка, экспорт и preview импорта; `src/main.ts` координирует загрузку, применение настроек и атомарное восстановление.
- `src/training/constraints.ts` — правила точной высоты и произвольного интервала; `src/app/writer-lock.ts` — право единственного пишущего экземпляра. Миграции базы/JSON версий 1/2 находятся в `src/storage`.
- `src/ear/index.ts`, `src/audio/cue.ts`, `src/ui/ear.ts` — чистая слуховая модель, короткий native cue и UI; `src/route/index.ts`/`src/ui/route.ts` — активный таймер и глобальная панель. Корневой координатор хранит их результаты через общую очередь.
- `src/harmony/index.ts`, `src/audio/harmony.ts`, `src/ui/harmony.ts` — чистые четыре такта, native Web Audio/три bus и сопровождение; `tests/harmony.test.ts`, `tests/harmony-audio-plan.test.ts`, `tests/harmony-browser.mjs` и fixture проверяют план/PCM/live/UI. Буквальный `tests/fixtures/v3-backup.json` поддерживает независимую миграцию прежней схемы в 4.
- `tests/music.test.ts`, `tests/training.test.ts`, `tests/results.test.ts` — модульные эталоны; `tests/browser.mjs` и `tests/training-browser.mjs` — действия в изучении и обучении.
- `tests/audio-plan.test.ts` — чистые аудиопроверки; `tests/audio-browser.mjs` — PCM/live/UI; `tests/fixtures/audio.html` импортирует настоящий движок отдельно от продукта.
- `tests/storage-model.test.ts` и `tests/write-queue.test.ts` — модель данных/очередь; `tests/storage-browser.mjs` — нативная IndexedDB, отказ/rollback и UI; `tests/fixtures/storage.html` — изолированный фактический адаптер.
- `tests/constraints.test.ts` и расширенный training/storage набор — новые правила/миграция; `tests/release-browser.mjs`, `tests/fixtures/migration.html` и буквальный `v1-backup.json` — нативное обновление, полный сценарий и две вкладки.
- `tests/ear.test.ts`, `tests/cue.test.ts`, `tests/route.test.ts` — чистые правила/таймлайн; `tests/ear-browser.mjs`, `tests/fixtures/ear.html` — настоящий PCM/live/UI и native hidden. Реальный legacy v2 сохранён в `tests/fixtures/v2-backup.json`.
- `scripts/serve.mjs` — локальная раздача собранных файлов. `dist`, `node_modules` и `test-results` игнорируются Git.

Корневые зависимости: TypeScript 7.0.2, Vite 8.3.6, Vitest 5.1.0, Playwright 1.65.0, Tone.js 15.1.22. Версии закреплены корневым lockfile. Синтез и остальные ресурсы включены в локальную сборку, сетевых шрифтов/семплов нет.

## Работа с версией 1.2.0

«Изучение» показывает карту и связи. «Задания» запускает отдельную серию из шести типов, по умолчанию десять вопросов. «Найди ноту» допускает разные октавы, «Найди высоту» — только указанную (например, A1). «Найди ступень» использует выбранную структуру, «Найди интервал» — все ноты области и явный интервал от тоники. Подсказка, пропуск и исправление имеют разные результаты. При изменении области или режима старая серия закрывается; для продолжения нужен новый старт.

«Последовательности» показывает маршрут и плеер: темп, длительность, отсчёт, фрагмент, один проход/цикл/лестницу, метроном и раздельную громкость. Структурные параметры редактируются до старта или после стопа; при обычном повторе можно менять BPM во время игры. Нажать «Старт» для разрешения звука браузером. Space управляет стартом/паузой/продолжением, Escape останавливает; в интерактивных полях сокращения не перехватываются. Скрытие вкладки ставит практику на паузу до явного продолжения.

Раздел «Слух» предлагает тонику/мажорное или минорное трезвучие, 1–20 вопросов и темп 60–120 BPM. «Прослушать» играет тонику, паузу и цель; кнопки 1/3/5 открываются после конца. Повтор звука, показ ответа и пропуск имеют разные результаты. Остановленный/скрывшийся cue нужно прослушать заново целиком; перезагрузка не запускает звук автоматически.

«Маршрут занятия» задаёт 3 минуты грифа, 3 слуха и 4 практики. «Начать маршрут» открывает первый блок и глобальную панель. Пауза/скрытие останавливают активный счёт; продолжение и переход явные. Ранний переход/стоп оставляют фактическое время. Статистика маршрута — время таймера, не оценка игры/внимания.

«Аккомпанемент» играет C–F–G–C в 4/4, бас 1–3–5–3, аккордовую гармонию и клик. Выбрать 40–220 BPM, отсчёт/повтор, нажать «Старт». Выключить бас в микшере, чтобы играть свою партию; громкости и mute доступны на ходу. Темп/отсчёт/повтор меняются после «Стоп». Дробная пауза/продолжение сохраняют место без нового отсчёта; hidden требует явного продолжения, уход из раздела останавливает звук. Space/Escape действуют с теми же guards полей/кнопок. Позиции предпросмотра — примеры звучащих нот, не подбор лучшей аппликатуры.

Настройки и каждое фактическое действие экранной серии автоматически сохраняются в базе `bass-study` этого профиля на `http://localhost:4173`; статус виден над занятием. «Сохранение…» ещё не означает завершённую запись: перед закрытием дождаться подтверждения. При ошибке доступно «Повторить сохранение»; экспорт содержит подтверждённые данные. Перезагрузка сохраняет историю попыток, но не продолжает старый квиз/таймер: новое занятие получает отдельную запись. Если база не открылась при запуске, интерфейс прямо сообщает о временной памяти страницы — до её закрытия нужно скачать копию.

Одна вкладка владеет правом записи. Во второй контролы заблокированы с сообщением; закрыть первую и нажать «Проверить снова», чтобы загрузить свежие настройки. Это не совместное редактирование. Если браузер не предоставляет Web Locks, приложение объясняет требование поддерживаемого Edge.

Раздел «Мои занятия и настройки» различает экранные задания, ручные отметки, слух и маршруты; фильтр/сводки сохраняют источники отдельно. Пресеты содержат также раздел/настройки слуха и сопровождения. У незавершённого слухового вопроса цель скрыта в деталях. Ручная форма хранит комфортный BPM/заметку и время эталона без отсчёта/пауз; это не измерение реальной игры. При начале ввода фиксируются материал и время; смена раздела/запуска не переносит старую заметку на новый материал. Для переноса есть явное действие формы, для обновления времени — отдельная кнопка.

«Экспортировать JSON» скачивает компактный снимок схемы **4**. Принимаются версии 1/2/3/4 до **64 МиБ UTF-8**, включая прежние форматированные копии. Preview ничего не меняет, подтверждение полностью заменяет данные одной транзакцией; текущую копию можно экспортировать заранее. Базы 1/2/3 обновляются автоматически; ошибка старой записи отменяет upgrade без сброса. Исходные события/даты сохраняются. Размер файла не гарантирует RAM/квоту; большой импорт и первое полное чтение могут задерживать страницу.

Адаптер `readSnapshot()` использует подтверждённый замороженный кеш под единственным writer lease; `readSnapshot({fresh:true})` предназначен для явного чтения внешних изменений. Обычные записи обновляют кеш после commit. История строит тело при открытии; это не альтернативный источник постоянных данных. Подробный контракт — в архитектуре.

Браузер может очистить локальные данные. Копии хранить вне профиля браузера; GitHub не содержит историю занятий. `localhost`, `127.0.0.1` и другие порты дают разные области данных. Проигранный эталон не получает автоматическую оценку исполнения на инструменте.

## Отдельный стенд P1: первичная подготовка

```powershell
npm.cmd --prefix experiments/p1 ci --no-fund --no-audit
npm.cmd --prefix experiments/p1 run build
```

Первичная установка требует доступа к npm registry. Сборка включает проверку TypeScript и создаёт игнорируемую Git папку `experiments/p1/dist`. Исходные файлы, lockfile и все необходимые ресурсы остаются локально; стенд не обращается к CDN.

## Стенд P1: запуск

```powershell
node experiments/p1/server.mjs
```

Открыть [http://localhost:4173](http://localhost:4173). Остановить сервер сочетанием Ctrl+C в его терминале. Сервер раздаёт только содержимое `dist` и слушает loopback `127.0.0.1`; этот локальный процесс должен оставаться запущенным. Наличие Node.js требуется и после сборки для выбранного способа запуска.

При занятом порте процесс завершается с `EADDRINUSE`, без выбора другого порта. Не менять `localhost` на `127.0.0.1` и не выбирать случайный порт для обычных занятий: это другой origin и другое браузерное хранилище. Переменная `BASS_P1_PORT` существует для эксперимента; автоматические проверки используют именно 4173.

## Стенд P1: возможности

- Эталонные синтезированные ноты, отсчёт, цикл, ручная смена темпа, пауза и остановка.
- Синтетические настройки, два пресета и два результата разного происхождения; отдельная IndexedDB-база `bass-study-p1-storage`.
- Экспорт в текстовое поле, предварительная проверка и подтверждаемая полная замена тестовых данных.
- Диагностика состояния звука. Это техническая информация стенда, которую не требуется переносить в пользовательский интерфейс тренажёра.

Проба использует короткий двухдольный отсчёт и ускоренный темп для автоматических проверок; продуктовые значения определены требованиями. Музыкальный гриф, полноценные квизы, немые такты и лестница темпа здесь ещё не реализованы. Формат синтетических записей не является утверждённой полной схемой будущего продукта.
