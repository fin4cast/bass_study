# План разработки bass_study

План содержит открытые задачи, открытые вопросы и отложенные идеи. Поведение описано в [требованиях](REQUIREMENTS.md), устройство — в [архитектуре](ARCHITECTURE.md), причины выбора — в [решениях](DECISIONS.md), назначение — в [целях](GOALS.md). История выполненных работ — в git.

## Как пользоваться планом

- Статусы задач: **не начата**, **в работе**, **выполнена**, **заблокирована**. У блокировки указывается причина и действие, которое её снимает.
- Задача выполнена, когда получен её результат и пройдена проверка. Начатая работа или написанный код сами по себе этого не подтверждают.
- В задаче указываются ID требований, а не их текст. Изменение поведения сначала отражается в требованиях, изменение подхода — в решениях и архитектуре.
- Идея из раздела «Отложенные идеи» становится задачей только по поручению пользователя, с определёнными сценарием, границами и критериями приёмки.
- Выполненная задача удаляется из плана; её ID не переиспользуется.
- План не содержит календарных обещаний.

## Открытые вопросы

| Вопрос | Рекомендуемый вариант | Последствия и способ проверки |
| --- | --- | --- |
| Испытание с настоящим басом и USB-интерфейсом ([R-020](REQUIREMENTS.md#r-020), [R-014](REQUIREMENTS.md#r-014)) | Провести отдельное занятие с инструментом пользователя: задержка, устойчивость низких нот, уровень и фон для аудиовхода; слышимость и тембр эталонов | До испытания аудиовход остаётся диагностикой, а заявления о точности и задержке не делаются. Результат фиксируется в требованиях; автоматическая оценка игры требует отдельного решения |
| Первое полное чтение большой истории идёт в главном потоке ([D-021](DECISIONS.md#d-021)) | Не менять, пока задержка не заметна на реальной истории | Если задержка появится — рассмотреть чтение в Worker или постраничную загрузку; проверять на синтетической истории в Edge, не выдавая локальный замер за гарантию |
| Чем рисовать TAB и ноты на экране игры (P13-03) | Взять существующий VexFlow ([D-024](DECISIONS.md#d-024)), если TAB и стан помещаются в сцену 1280×720 с курсором. Иначе собственный SVG-TAB, как в референсе VIS-11 r1, и стан по запросу | Проверить в Edge время отрисовки, читаемость с расстояния игры и движение курсора по аудиочасам; оба варианта читают один план `createNotationPlan` |

<a id="ideas"></a>
## Отложенные идеи

Идеи не утверждены и не реализуются без поручения. Полный список направлений — [R-015](REQUIREMENTS.md#r-015).

| Идея | Почему отложена |
| --- | --- |
| Интервальное повторение и программа занятий | Нужна накопленная история реальных занятий и выбор алгоритма, при котором ошибки не вытесняют освоенное |
| Слух в тональности, короткие диктанты | Нужны учебные уровни, тембр и объяснение ошибок; базовый слуховой модуль ограничен ступенями трезвучия ([R-016](REQUIREMENTS.md#r-016)) |
| Аудиооценка игры: высота и атаки | Нет измерений задержки и устойчивости на настоящем инструменте; без них оценка была бы недостоверной |
| Сохранение высоты при замедлении аудиозаписей (time-stretch) | Сейчас varispeed ([D-025](DECISIONS.md#d-025)); time-stretch требует отдельного движка и проверки качества |
| Автоматическое выделение инструментов из записи | Требует тяжёлых вычислений или внешнего сервиса; базовые занятия не должны от этого зависеть |
| Редактор партитур, библиотека песен | Вне целей первой версии ([цели](GOALS.md#границы-проекта)) |
| Другие строи, 5-струнный бас, телефон | Подтверждённый сценарий — 4 струны E–A–D–G на Windows; нужна реальная потребность, управление и перенос данных |
| Другие браузеры, скринридер, сон ОС и смена аудиоустройства | Не проверялись; поддержка не заявляется до отдельной проверки |
| Вторая вкладка только для чтения | Сейчас при занятом праве записи вторая вкладка полностью отключается, даже гриф. Разрешить чтение без записи — продуктовое решение владельца; потребует проверки, что ни один путь не пишет без права |
| Плавная громкость в проигрывателе последовательностей | `engine.ts` меняет громкость голосов ступенькой (`setValueAtTime`), как раньше дорожки; щелчки возможны, но жалоб и измерений нет |
| Освобождение слушателей alphaTab при повторной загрузке партитуры | Замер в Edge показал рост на несколько JS-слушателей за загрузку вне кода приложения; заметного влияния нет |
| Переход браузерных раннеров на `@playwright/test` | Свои раннеры с быстрым и полным набором и параллельным пулом укладываются в цель по времени; переход даст стандартные отчёты и повторы ценой переписывания всех сценариев |
