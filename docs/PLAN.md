# План разработки bass_study

План содержит открытые задачи, открытые вопросы и отложенные идеи. Поведение описано в [требованиях](REQUIREMENTS.md), устройство — в [архитектуре](ARCHITECTURE.md), причины выбора — в [решениях](DECISIONS.md), назначение — в [целях](GOALS.md). История выполненных работ — в git.

## Как пользоваться планом

- Статусы задач: **не начата**, **в работе**, **выполнена**, **заблокирована**. У блокировки указывается причина и действие, которое её снимает.
- Задача выполнена, когда получен её результат и пройдена проверка. Начатая работа или написанный код сами по себе этого не подтверждают.
- В задаче указываются ID требований, а не их текст. Изменение поведения сначала отражается в требованиях, изменение подхода — в решениях и архитектуре.
- Идея из раздела «Отложенные идеи» становится задачей только по поручению пользователя, с определёнными сценарием, границами и критериями приёмки.
- Выполненная задача удаляется из плана; её ID не переиспользуется.
- План не содержит календарных обещаний.

<a id="p18"></a>
### P18. Программа обучения: этапы, линии и шаги

Поручение пользователя от 2026-11-16 ([D-051](DECISIONS.md#d-051)): программа [R-028](REQUIREMENTS.md#r-028) вместо семи целей. Что строить — в R-028 и его [дополнении](REQUIREMENTS.md#r-028-content) (правила нот и контрольные примеры); здесь — порядок.

**Как вести работу.** Заход — законченный кусок: после него приложение собрано, проверки по [правилам](../AGENTS.md) зелёные, сделанным можно заниматься. Заходы идут по порядку; внутри захода задачи идут в порядке таблицы. Новая сессия начинает с первой задачи не в статусе «выполнена» и читает её раздел R-028 и дополнения.

**Правила всех заходов.**
- Хранимые формы меняются один раз — в P18-20; история и прогресс сбрасываются тогда же. После него допускаются только новые шаблоны и новые значения списков ([A1](REQUIREMENTS.md#r-028-content), [B7](REQUIREMENTS.md#b-forms-change)).
- Программа появляется по этапам: данные этапа добавляются в его заходе. Шаги следующих этапов до своего захода в «Основах» не показываются; их материал доступен в библиотеке.
- У каждой задачи с новым шаблоном, рисунком или последовательностью есть unit-тесты по контрольным примерам дополнения; у каждого нового экранного пути — один сценарий в быстром наборе, подробные варианты — в полном. Быстрый набор остаётся в пяти минутах.
- [Архитектура](ARCHITECTURE.md) приводится к коду в том же заходе, где меняется устройство; требования R-026 и R-027 — когда заменяемое поведение убрано.
- Экраны делаются без отдельного цикла макетов ([D-051](DECISIONS.md#d-051)); если пользователь потребует макеты, перед задачей экрана добавляется задача утверждения.

| Испытание с настоящим басом и USB-интерфейсом ([R-020](REQUIREMENTS.md#r-020), [R-014](REQUIREMENTS.md#r-014)) | Провести отдельное занятие с инструментом пользователя: задержка, устойчивость низких нот, уровень и фон для аудиовхода; слышимость и тембр эталонов | До испытания аудиовход остаётся диагностикой, а заявления о точности и задержке не делаются. Результат фиксируется в требованиях; автоматическая оценка игры требует отдельного решения |
| Первое полное чтение большой истории идёт в главном потоке ([D-021](DECISIONS.md#d-021)) | Не менять, пока задержка не заметна на реальной истории | Если задержка появится — рассмотреть чтение в Worker или постраничную загрузку; проверять на синтетической истории в Edge, не выдавая локальный замер за гарантию |

<a id="ideas"></a>
## Отложенные идеи

Идеи не утверждены и не реализуются без поручения. Полный список направлений — [R-015](REQUIREMENTS.md#r-015).

| Идея | Почему отложена |
| --- | --- |
| Динамика и ghost notes в эталоне и упражнениях | Синтез эталона не передаёт силу и глушёные ноты; нужна модель громкости ноты ([D-050](DECISIONS.md#d-050)) |
| Окно подтверждения (`ui/confirm.ts`) не возвращает фокус, если пользователь уже перевёл его до запоздавшего `close` | Та же гонка, что исправлена в диалогах «Настроек»; сбоя в тестах нет, а после удаления фокус ставит вызывающий код |
| Запись своего подхода с аудиовхода и прослушивание поверх клика или эталона | Самооценка без записи завышается; нужен путь записи и хранения звука ([R-020](REQUIREMENTS.md#r-020)) — ревью P17 |
| Шаффл (`tripletFeel`) партитуры и игра фрагмента под остальные партии песни | Фрагмент хранит ровные шестнадцатые и только басовую партию ([R-024](REQUIREMENTS.md#r-024-p14)) |
| Счёт «1 е и а» для шестнадцатых в строке ритма и TAB | Строка счёта зависит от реальной сетки такта, а не от рисунка; затрагивает TAB |
| Пояснения недоступных подписей и лестницы текстом, а не только в подсказке | Новая разметка у переключателей на всех ширинах и визуальные матрицы |
| Пальцы правой руки (i/m) в TAB | Меняется высота TAB (`tabGeometry`) во всех видах |
| Оценка неоценённого подхода при уходе с экрана игры | Нужен вопрос при уходе; сейчас подход продолжается до оценки только на самом экране |
| Неоценённый подход при сбое запуска звука | Сейчас при отказе `port.start` после продолжения подхода сыгранное пропадает с видимой ошибкой; нужен отказ звука в тестовой фикстуре, чтобы закрыть тестом — ревью P17-fix |
| Неполный проход и темп соседних упражнений шаблона | «Не успевал» за неполный проход (0 проходов) попадает в историю и может задать −4 упражнению того же шаблона без запомненного темпа — ревью P17-fix |
| Лига во фрагменте: «(5)» в TAB у начала петли и лига от верхней ноты двойной ноты | Звук в обоих случаях верный (атака в начале петли), неточен только вид TAB; лига берёт нижнюю ноту прошлого такта — ревью P17-fix |
| Tap tempo и настройка шага лестницы | Убрано из P17 ради простоты транспорта; вернуть по запросу ([D-050](DECISIONS.md#d-050)) |
| Интервальное повторение | Программа [R-028](REQUIREMENTS.md#r-028) обходится пометкой «пора повторить»; алгоритм нужен только при накопленной истории реальных занятий ([D-051](DECISIONS.md#d-051)) |
| Слух в программе обучения: «Эхо» без видимых нот и со случайной фразой, повтор ритма на слух, «выше или ниже» | Пользователь отложил слух: сначала программа R-028 ([D-051](DECISIONS.md#d-051)) |
| «Нижняя» позиция последовательности: тоники на 1-м ладу и открытых струнах | Закрытая позиция ставит F на A/8, поэтому I–IV–V в C идёт на ладах 3–10; третье значение `position` версию не меняет, но правило не написано ([дополнение R-028](REQUIREMENTS.md#b-position)) |
| Слух в тональности, короткие диктанты | Нужны учебные уровни, тембр и объяснение ошибок; слуховой вопрос ограничен ступенями трезвучия и пентатоники ([R-016](REQUIREMENTS.md#r-016)) |
| Аудиооценка игры: высота и атаки | Нет измерений задержки и устойчивости на настоящем инструменте; без них оценка была бы недостоверной |
| Сохранение высоты при замедлении аудиозаписей (time-stretch) | Сейчас varispeed ([D-025](DECISIONS.md#d-025)); time-stretch требует отдельного движка и проверки качества |
| Автоматическое выделение инструментов из записи | Требует тяжёлых вычислений или внешнего сервиса; базовые занятия не должны от этого зависеть |
| Редактор партитур, библиотека песен | Вне целей первой версии ([цели](GOALS.md#границы-проекта)) |
| Другие строи, 5-струнный бас, телефон | Подтверждённый сценарий — 4 струны E–A–D–G на Windows; нужна реальная потребность, управление и перенос данных |
| Другие браузеры, скринридер, сон ОС и смена аудиоустройства | Не проверялись; поддержка не заявляется до отдельной проверки |
| Вторая вкладка только для чтения | Сейчас при занятом праве записи вторая вкладка полностью отключается, даже гриф. Разрешить чтение без записи — продуктовое решение владельца; потребует проверки, что ни один путь не пишет без права |
| Плавная громкость в проигрывателе последовательностей | `engine.ts` меняет громкость голосов ступенькой (`setValueAtTime`), как раньше дорожки; щелчки возможны, но жалоб и измерений нет |
| Освобождение слушателей alphaTab при повторной загрузке партитуры | Замер в Edge показал рост на несколько JS-слушателей за загрузку вне кода приложения; заметного влияния нет |
| Переход браузерных раннеров на `@playwright/test` | Свои раннеры с быстрым и полным набором и параллельным пулом укладываются в цель по времени; переход даст стандартные отчёты и повторы ценой переписывания всех сценариев |
| Один хелпер оболочки для браузерных раннеров | `tests/helpers/data-ui.mjs` и `shell-data-ui.mjs` почти совпадают; сведение — чистка тестов без изменения поведения |
| Убрать или вернуть VexFlow | После P13 `ui/notation.ts` в продукте не смонтирован ([D-043](DECISIONS.md#d-043)), его держит только fixture. Удаление зависимости или нотный стан на экране игры — решение владельца |
| Экраны «Занятия» на узкой ширине | На 390 px «Сегодня» и экран игры прокручиваются по горизонтали; ориентир VIS-11 начинается с 1024×768, телефон вне целей |
