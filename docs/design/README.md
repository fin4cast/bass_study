# Визуальные ориентиры bass.study

Дата начала: **2026-11-08**. Пользователь поручил последовательно сравнить и утвердить по 2–3 функционально разным UX-референсам для основных экранов. Сейчас прорабатывается **только VIS-01, гриф**, пакет **r3**; остальные экраны перечислены как очередь последующего согласования. Базовое направление — **«Мастерская» с левым меню навигации**. Конкретное исполнение грифа и экран целиком ещё не утверждены.

Назначение продукта сохраняется в [целях](../GOALS.md), реализованное и принятое поведение — в [требованиях](../REQUIREMENTS.md), порядок разработки — в [плане](../PLAN.md). Существенные принятые решения записываются в общий [журнал решений](../DECISIONS.md). Этот каталог хранит сравниваемые варианты и точную основу для последующей реализации.

## Как согласовываем

1. Для одного экрана подготавливаем 2–3 варианта на одинаковом материале. Варианты различаются основным действием, расположением управления, способом раскрытия информации и учебным сопровождением. Смена палитры сама по себе отдельным вариантом не считается.
2. Вместе с вариантами сохраняем сценарий, полезную инфографику, компромиссы и критерии сравнения. Инфографика должна объяснять музыкальную связь, положение, порядок или состояние; каждая дополнительная область требует конкретной пользы для занятия.
3. Пользователь выбирает направление и необходимые изменения. Общая положительная оценка направления не равна утверждению конкретного варианта.
4. Дорабатываем выбранный вариант. После явного утверждения записываем его ID, ревизию, дату, существенные детали и оставшиеся вопросы; сохраняем исходник и проверенные снимки. Предыдущие кандидаты остаются доступными для истории.
5. Переходим к следующему экрану. Новые варианты учитывают уже утверждённую навигацию, типографику и семантику цветов.

Выбор UX-референса и готовность продуктовой реализации — отдельные состояния. Прототип не доказывает корректность аудио, сохранения, доступности или обучения. Новые возможности из кандидатов уточняются в требованиях перед реализацией; существующие проверки продукта продолжают действовать.

## Что сохраняем для каждого экрана

- Карточку экрана: назначение, исходные данные, состояния, сравнение и статус выбора.
- Интерактивные кандидаты с явным обозначением концепции и локальными демонстрационными действиями.
- Проверенные снимки с указанием размера окна и темы, когда такая проверка фактически выполнена.
- После утверждения — точную ревизию, выбранные детали и границы будущей реализации. Неутверждённые варианты не становятся источником требований автоматически.

Текущие материалы первого экрана: [карточка VIS-01](screens/01-fretboard.md), [исходник r3](references/fretboard-r3.fragment.html), [автономный HTML r3](references/fretboard-r3.html). Сравниваются те же три исполнения грифа внутри одинаковой «Мастерской», с исправленной геометрией и размером нот: [Точный гриф](references/fretboard-r3-precise.png), [Инструментальный](references/fretboard-r3-instrument.png), [Связи на грифе](references/fretboard-r3-connections.png). Это развитие выбранной модели, а не три новые UX-модели. HTML открывается отдельно от продуктового занятия; его демонстрационные состояния не являются пользовательской историей.

Уточнение пользователя: общий визуальный стиль в целом устраивает; доработки нужны прежде всего самому грифу — акцент, контраст и качество реализации. Левая навигация сохраняется во всех вариантах. Выбор базовой модели не считается финальным утверждением экрана.

Актуальное прямое указание: показывается **весь выбранный диапазон**, по умолчанию **0–12**, и все четыре строки **G, D, A, E**. Поле «Диапазон» независимо от формы; форма **5–8** задаёт восемь маркеров, а фильтр струн убирает только маркеры на соответствующих строках. Неиспользуемые области остаются без нот. В r3 сохраняются фиксированные размеры маркера **46 px** и подписи **18 px**; при недостатке ширины диапазон может переноситься на подписанные последовательные строки грифа с сохранением всех выбранных ладов и четырёх струн вместо сжатия или обрезки.

Сохранённый пакет [r2](references/fretboard-r2.html) отражает ошибочную интерпретацию агента: постоянный холст 0–24 был принят за указание пользователя. Это не требование пользователя и не основание текущего дизайна. Пользователь также указал на слишком мелкие ноты r2 относительно текущего приложения и прислал пример с крупными маркерами. [Исходник r2](references/fretboard-r2.fragment.html) и его снимки сохранены как история без изменений; приоритет r3 — читаемость выбранного диапазона.

История r1 сохранена: [исходник](references/fretboard.fragment.html), [автономный HTML](references/fretboard.html), снимки [Мастерская](references/fretboard-workshop.png), [Пошаговое изучение](references/fretboard-guided.png), [Атлас связей](references/fretboard-atlas.png). Для этих снимков использованы светлая тема, окно 1366×1100 и область приложения 1318×810. Границы фактических проверок r1/r2 записаны в [карточке VIS-01](screens/01-fretboard.md#проверки-r1); они не распространяются автоматически на r3.
