# VIS-11. Экран игры

Ревизия: **r1**. Статус: **на рассмотрении** — три кандидата подготовлены для выбора пользователя, ни один не утверждён. Основание — [D-043](../../DECISIONS.md#d-043), поведение — [R-026](../../REQUIREMENTS.md#r-026) и [R-027](../../REQUIREMENTS.md#r-027). Экран заменяет отложенные VIS-03 «Последовательности» и игровую часть VIS-07 «Маршрут занятия».

Материалы: [автономный HTML](../references/lesson-r1-vis11.html) с переключателями кандидата и темы · [редактируемый view](../references/lesson-r1-vis11.view.html) · [общий каркас](../references/lesson-r1.common.html) · [модель](../references/lesson-r1.model.ts) · снимки в [разделе проверок](#проверки-r1).

## Назначение

Пользователь выбрал упражнение и играет его на басу. Экран отвечает на три вопроса без прокрутки: **что играть сейчас** (TAB и/или гриф с текущей и следующей нотой), **в каком темпе** (транспорт) и **что дальше** (самооценка после прохода и предложение следующего шага). Теория появляется по месту: свёрнутой карточкой понятия упражнения. Слух — опция «Сначала услышь», а не отдельный раздел. Цели — [G-001](../../GOALS.md#g-001), [G-002](../../GOALS.md#g-002), [G-003](../../GOALS.md#g-003).

Главное отличие от прежних «Последовательностей»: игровая сцена (TAB, гриф, транспорт) целиком помещается в окно 1280×720. Прежде гриф уходил под сгиб, а темп, отсчёт и повтор были разнесены по раскрывашкам.

## Общий материал

Все кандидаты показывают **EX-1 «Связка соседних форм · пентатоника Am · A → B»**. Это вверх по форме A (лады 5–8), затем переход сдвигом третьего пальца по струне G на два лада и вниз по форме B (лады 7–10). 16 восьмых, два такта. Позиции, ноты, ступени, пальцы и TAB вычисляются продуктовыми функциями `getBoxCatalogue`, `createSequence` и `createNotationPlan`. Порядок задаёт вспомогательная функция референса `connectBoxes` — кандидат для R-026, а не поведение продукта.

## Общее для всех кандидатов

- Оболочка нового меню [D-043](../../DECISIONS.md#d-043): **Занятие · Гриф · Ритм · Песни · Прогресс**, внизу «Настройки» и тема. Без фотографии в меню: на экране игры высота нужна сцене.
- Заголовок упражнения:
  - возврат к плану занятия и номер шага;
  - чипы понятий R-027;
  - лучший комфортный темп.
- **Транспорт одной строкой:**
  - Играть/Стоп (пробел);
  - BPM ± (темп в четвертях ♩, игра восьмыми);
  - отсчёт 4;
  - по кругу;
  - лестница темпа;
  - номер ноты и прохода.

  Один транспорт и один темп на экран, вместо прежних трёх независимых.
- **Гриф** по приёмам VIS-01 r5: строки G-D-A-E, тоника золотая, форма A светлая, форма B голубая, общие ноты сиреневые. Тоника на общей позиции (D/7) — золотое кольцо внутри сиреневой. Текущая нота жёлтая с белым кольцом, следующая обведена пунктиром. Пальцы берутся из формы, которую сейчас играют.
- **TAB** — собственный SVG по событиям `createNotationPlan`: четыре линии, лады, счёт «1 и 2 и», такты, курсор. Нотный стан в r1 не показан; гравировка в продукте — открытый вопрос [плана](../../PLAN.md#open).
- **После прохода** — «Чисто / С ошибками / Не успевал» и предложение: темп +4 или следующая связка, петля на ноты 5–12 с переходом между формами, темп −4. Самооценка встаёт на место карточки понятия (A, B) или под TAB (C), транспорт остаётся на экране. Это самооценка, приложение игру не оценивает.

## Кандидаты

| Кандидат | Компоновка | Польза | Компромисс |
| --- | --- | --- | --- |
| **A · Таб над грифом** | Полная строка TAB (16 нот) над грифом 0–12; сегменты подсказок «Таб + гриф / Таб / Гриф / По памяти» и подписей «Ноты / Ступени / Пальцы» | Читается всё упражнение сразу; гриф показывает связь форм на всей шее; подсказки снимаются явно | Два крупных поля делят высоту; маркеры грифа 40 px вместо 46 px утверждённого r5 |
| **B · Гриф главный** | Крупный гриф 3–12 (маркер 46 px, как в r5); над ним лента TAB текущего такта и карточка «Сейчас: нота · позиция · ступень»; явная подпись перехода между формами | Лучше видны геометрия и переход; удобно новичку, который ещё не читает TAB | Чтение TAB тренируется меньше; всё упражнение целиком не видно |
| **C · Фокус** | Крупный TAB одного такта со следующим тактом ниже; справа мини-гриф 4–11 без подписей и «шаги подсказок» Таб + гриф → Только таб → Только гриф → По памяти | Ведёт от подсказки к игре по памяти; крупный TAB читается с расстояния от инструмента | Мини-гриф мелкий и без подписей; шаги подсказок добавляют правило перехода, которое нужно описать в R-026; рядом с лестницей темпа это второе «пошаговое» правило |

## Состояния и демо-действия

| Действие или состояние | Что должно быть понятно |
| --- | --- |
| До старта | Первая нота отмечена как следующая; транспорт показывает темп и «Нота 0 из 16» |
| Отсчёт | «Отсчёт 1…4» рядом с темпом; затем курсор и подсветка синхронно идут по TAB и грифу |
| Игра по кругу | Номер прохода растёт; после прохода появляется самооценка, игра не прерывается, транспорт не уходит за край окна |
| Смена подсказок (A и C) | Скрытое поле убирается целиком вместе с легендой; «По памяти» оставляет только стартовую позицию |
| Подписи «Ноты / Ступени / Пальцы» (A и B) | Те же позиции, другой смысл подписи; пальцы соответствуют играемой форме |
| «Сначала услышь» | Слух как опция упражнения (в референсе без звука) |
| Тёмная тема и окна 1440×900, 1280×720, 1024×768 | Сцена читается; прокрутки нет |

## Критерии выбора

1. Видно ли без прокрутки, что играть, в каком темпе и что делать после прохода?
2. Понятен ли переход между формами и зачем он нужен (карточка понятия)?
3. Удобно ли читать с инструментом в руках, на расстоянии 60–80 см от экрана?
4. Как кандидат поддерживает постепенный отказ от подсказок?
5. Сколько нового правила требует кандидат от продукта (шаги подсказок, лента)?

**Мнение независимого ревью** — это рекомендация агента, а не выбор пользователя.

- Сильнее всего A как основа: в нём меньше всего новых правил и есть явное снятие подсказок.
- Предложенная комбинация: A + окно грифа и маркеры B (3–12, не меньше 46 px) + строка «Переход» из B + более крупный TAB (около 20 px).
- Шаги подсказок C не делать отдельной панелью: после чистого прохода давать текстовое предложение «попробуй „Только таб“».
- Отдельные сильные стороны: крупный TAB с видом следующего такта — у C, объяснение перехода — у B.

## Границы r1

Референс не воспроизводит звук, не пишет историю и не проверяет доступность или пользу для обучения. Курсор идёт по таймеру страницы, а не по аудиочасам. Данные «лучший темп 76», «чисто · 72» и номер шага плана — демонстрационные. Нотный стан и VexFlow не используются. Окончательные размеры маркеров и шрифтов уточняются при утверждении.

## Материалы и сборка

Из корня репозитория:

```powershell
node docs/design/references/prepare-lesson-r1.mjs   # модель + контрольные примеры + фрагменты
node docs/design/references/render-lesson.mjs       # автономные lesson-r1-vis10.html и lesson-r1-vis11.html
```

`lesson-r1.model.ts` переэкспортирует чистые функции `src/music`, `src/training` и `src/notation`. Манифест `lesson-r1.model.json` хранит хеши входов и контрольные примеры. Фрагменты и автономный HTML — производные файлы, вручную не правятся. URL-параметры: `?candidate=a|b|c&theme=light|dark&capture`.

При 1280×720 и 1024×768 у всех кандидатов нет вертикальной прокрутки рабочей области ни во время игры, ни после первого прохода с открытой самооценкой.

Независимое ревью шести кандидатов нашло 16 дефектов, все исправлены до снимков:

- неверные пальцы и окраска общих нот;
- переполнение после прохода;
- вёрстка C при 1024;
- подсказка о петле;
- единица темпа;
- шкала самооценки;
- запись позиций (E/8 в интерфейсе);
- тексты.

Чтение с расстояния 60–80 см оценено только по пиксельным размерам, с инструментом не проверялось.
