## Три разных уровня проверки звука

**PCM:** `renderCueOffline` возвращает настоящий mono AudioBuffer 44,1 кГц. Из samples извлекаются два начала с RMS-окном 5 мс и частоты по переходам через ноль; независимые ожидаемые Hz заданы в тесте. При 120 BPM тоника идёт с 0, цель — с 1 с, между ними тишина; буфер 1,6 с включает 0,1 с хвоста. Начала сравниваются с допуском 20 мс, частоты — 0,1 Гц; это параметры метода, не обещание физической задержки.

| Контекст | Эталонные reference → target | Измерено из PCM, Гц |
| --- | --- | --- |
| C major | C2 → E2 | 65,406394 → 82,406888 |
| A minor | A2 → C3 | 109,999997 → 130,812788 |
| C♯ major | C♯2 → E♯2 | 69,295654 → 87,307062 |

Во всех трёх примерах два начала (0 и примерно 0,9973 с с учётом окна), RMS паузы и хвоста **0**, RMS тонов ненулевой. Это проверяет регистр/интервал и энгармоническое написание модели; не реалистичность тембра.

**Live/UI:** настоящий пользовательский старт даёт ненулевой сигнал анализатора, callback наступает по AudioContext-clock после фактического конца; stop в паузе отменяет уже запланированную цель, три старта не завершают отменённые запуски. Для ответа на случайный UI-вопрос initScript наблюдает реальные native `oscillator.frequency.setValueAtTime` и выводит интервал из двух Hz. Это **не PCM** и не скрытый API правильного ответа; PCM проверяется отдельно. В продуктовом DOM/ARIA до ответа нет target/MIDI/готового correct-флага.

**Физический вывод:** системный выход браузеров приглушён. Динамики/наушники, задержка вывода, акустическая различимость человеком и реальный бас не испытывались. Слуховая статистика — выбор после звука, не измерение человеческого слуха по входному сигналу или качества игры.

## Слуховые ответы, приватность и данные

Проверены gating до конца трёх долей, первый самостоятельный ответ, replay без подмены hint/error, ошибка → исправление, показ/пропуск/next, отмена/повторный полный listen, смена настроек/раздела и настоящее скрытие вкладки. Callback старого запуска не открывает ответ нового вопроса. После hidden вопрос остаётся, но прежний неполный cue не засчитывается.

История `ear/audio-choice` хранит упорядоченные start/complete/cancel и answer events, исходный контекст, replay и исходы. Первое время ответа связано с первым complete; исправление не становится самостоятельным. У interrupted-вопроса глобальная панель показывает «цель скрыта», без target/MIDI-атрибутов, в том числе после reload. Ear-фильтр/сводки не входят в screen-accuracy; ручная отметка остаётся self-report.

Выбранный раздел и ear preferences сохраняются; фильтры струн/ладов не меняют фиксированный регистр слуха. Обычные UI-сценарии скачали JSON, добавили лишнюю ручную запись, выполнили preview/подтверждённую полную замену и получили точный прежний снимок после reload. Схема 3 приняла настоящие базы 1/2 и независимые старые JSON, сохранив события/даты; invalid legacy record отменил upgrade без сброса. Буквальный v2 fixture сохранён из фактической прежней базы, не создан новой фабрикой схемы 3.

## Активный маршрут

Чистые **9** примеров проверяют полный план `[180000,180000,240000]`, 600000 мс, границы/ожидание/события. Браузер использует реальные короткие интервалы без подмены clock и без десятиминутного ожидания. Таймер считает выбранный запущенный блок, не время игры/внимания.

В фактическом случае пауза при **922 мс** активного времени исключила примерно секунду ожидания; resume и ранний next открыли слух. Итог остановки: **[1197,242,0] мс**, не `[180000,180000,240000]`. Запись имеет `kind:route`, `source:active-timer`, finishReason stopped, без accuracy/independentCorrect. Native hidden поставил маршрут на паузу и возврат потребовал explicit resume.

Checkpoint после 5,5 с сохранил один history UUID, текст/фокус/caret ручного черновика; после stop фактический первый блок составил **6007 мс**, остальные 0. Нулевой старт намеренно не создаёт фиктивную историю: начальный проверяемый снимок публикуется после реального ненулевого времени/паузы. Сам план 10:00 не обещает столько же настенного времени и не дополняет ранние переходы до плана.

## Исправления и границы методики

Тесты обнаружили реальную ошибку обработчика маршрута: `closest('[data-route-step]')` находил диагностический атрибут контейнера бара и трактовал Resume/Next как навигацию с паузой. Выбор ограничен `button[data-route-step]`; ожидания правильного управления сохранены и финально прошли.

Отдельно исправлены тестовые предпосылки: нулевой start не обязан создавать запись; native Edge-случаи получили разные временные профили, чтобы не восстанавливать старые вкладки/lease. Обычный Playwright download event в native CDP `noDefaults:true` открывал `edge://downloads-hub` и не был надёжным способом финального чтения. Поэтому **только два native hidden-случая** проверяют подтверждённую историю readonly IndexedDB в собственном профиле. Обычные UI download/export/restore остались полноценными и прошли; проблема plumbing не выдаётся за отказ продукта.

Первый запуск при занятом 4173 остановился на setup без сценариев; вместо остановки неизвестного пользовательского процесса добавлен явный проверяемый reuse. Native hidden использует реальные вкладки/свойство `document.hidden`, без искусственных событий; ошибки содержат диагностические URL/статус страницы, а не скрываются ожиданием.

Ограничения P7-00 сохраняются: первое полное чтение большой истории блокирует главный поток, 64 МиБ не гарантируют RAM/квоту, масштаб новых ear/route типов отдельно не измерялся. Chrome/Firefox, скринридер, sleep/resume ОС и физическая аудиоаппаратура не испытаны.
