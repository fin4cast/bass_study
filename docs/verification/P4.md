# Проверка P4: звук, ритм и повторы

Дата: **2026-11-08**. P4-01–P4-03 выполнены. Продуктовые последовательности используют настоящий Tone.js/Web Audio, синхронную подсветку, метроном, фрагменты и лестницу темпа. Постоянное хранение и ручная форма результата остаются P5; весь MVP ещё не принят.

## Среда и воспроизведение

Windows 11 Pro 10.0.26300 x64; Node.js 24.18.0, npm 11.16.0, Microsoft Edge **157.0.4341.42**. Корневые TypeScript 7.0.2, Vite 8.3.6, Vitest 5.1.0, Playwright 1.65.0, Tone.js 15.1.22 закреплены lockfile.

Из корня репозитория после установки зависимостей:

```powershell
npm.cmd run build
npm.cmd test
npm.cmd run test:browser
npm.cmd run test:training
npm.cmd run test:audio
```

`build` включает проверку TypeScript. Браузерные команды выполнять последовательно с остановленным ручным сервером. Порт **4173** должен быть свободен; `test:audio` дополнительно требует **4181**. Runner сам запускает/закрывает production-сервер и Vite для изолированной fixture. Он отказывается подключаться к занятому порту. Фактический движок импортируется fixture с `127.0.0.1:4181`, продуктовый UI проверяется на `localhost:4173`. Это два тестовых origin, а не предложение менять адрес обычных занятий.

## Исправления, влияющие на корректность

При собственных реальных проверках обнаружен дефект resume: строковый дробный offset вроде `350.976i` в используемом пути Tone.js мог трактоваться как секунды и резко сдвигать сетку. Offset теперь создаётся через `Tone.TicksClass` с явными единицами. Независимая проверка закрепляет непрерывную сетку и правильный следующий звук; одной проверки тишины и ненулевого RMS для этого недостаточно. Вывод относится к нашему использованию Tone.js 15.1.22, а не ко всем возможным способам работы библиотеки.

Ранний callback конечной границы не должен завершать звук/курсор до наступления аудиовремени: движок различает `finishing` и `finished`. Пауза/стоп помечают отменённый lookahead как `cancelled`; такие события и ещё будущие времена исключаются из числа прозвучавших. Эти случаи проверены настоящими live-часами отдельно от чистого плана и offline-render.

## Пределы и следующий шаг

Системный выход тестовых браузеров приглушён. Проверены сигнал внутри Web Audio, PCM и интерфейс; физические динамики, различимость низких нот на акустике пользователя, субъективное качество тембра, задержка аудиовыхода и реальная игра басиста не измерялись. Проигрывание эталона не означает правильное исполнение пользователем.

Chrome/Firefox, скринридер, длительное занятие, сон/возобновление Windows, смена аудиоустройства и произвольное внешнее suspend контекста не испытаны. Нужна будущая пользовательская проверка тембра на своей акустике; она не заменяет уже выполненные технические проверки.
