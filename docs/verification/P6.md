# Проверка P6: первая версия и обновление данных

Дата: **2026-11-08**. Этап **выполнен**, базовый MVP **1.0.0** принят в указанных границах. Новые правила ответа, миграция, сохранение действий, writer lease и launcher проверены вместе с регрессиями после последней правки retiring guard.

Объём и основания: [R-001–R-014](../REQUIREMENTS.md), [D-018](../DECISIONS.md#d-018), [D-019](../DECISIONS.md#d-019). Следующие модули R-016–R-020 приняты отдельно в D-020 и не входят в готовность базового MVP.

## Метод и среда

Windows 11 Pro 10.0.26300 x64, Node.js 24.18.0, npm 11.16.0, Microsoft Edge 157.0.4341.42. Версия пакета — **1.0.0**; зависимости закреплены корневым lockfile. Новых библиотек для P6 не добавлено.

Production UI использует `http://localhost:4173`, fixture миграции — `http://127.0.0.1:4183`. Буквальный `tests/fixtures/v1-backup.json` не генерируется новой схемой. Нативную базу сначала создаёт старый формат, затем импортируется текущий адаптер: так проверяется настоящий `onupgradeneeded`, а не чтение данных, уже созданных версией 2. `window.p6` есть только у fixture. Проверки интерфейса используют обычные кнопки/поля и видимый prompt, без скрытого правильного ответа.

Чистые профили, отключённый кеш и блокировка запросов страницы вне loopback моделируют отсутствие интернета. Сетевой адаптер и фоновый трафик Windows не контролировались. Клавиатурный сценарий использует Tab/Enter/Space/стрелки/ввод, без программного `.click()` для действий занятия; экспорт скачивает фактический файл. Профиль пользователя не используется.

## Исправления по ревью

Нативный Web Lock освобождается после завершения очереди/закрытия адаптера, а не раньше: иначе отложенная внешняя запись могла заново открыть базу после передачи права второй вкладке. Retiring guard закрывает новые операции и позднее завершение инициализации. На уничтожение процесса браузер не обязан выделять время для произвольной async-работы; основная защита — запись после каждого фактического действия и видимый статус её завершения.

Детали истории показывают октаву точной цели и интервал, а незавершённая серия имеет видимую метку без необходимости раскрывать вложенные вопросы. История/ручная форма читают отдельный scope последовательности, чтобы временно неверное поле count не бросало исключение при рендере. Короткие SVG используют минимальную ширину viewBox, сохраняя обычный размер кружков и букв.

`start.cmd` реально запущен, сервер на `localhost:4173` вернул HTTP 200 и был остановлен. Кириллические сообщения первой версии CMD давали испорченную кодировку; после перехода на ASCII технические сообщения и `chcp 65001` повторный запуск дал HTTP 200 и чистый вывод. Интерфейс приложения остаётся русским. Первичная установка/сборка отдельны; launcher не включает Node.js и не означает проверку перезагрузки Windows.

## Пределы

Целевая среда — указанный Edge/Windows. Chrome/Firefox, скринридер, телефон, сон/возобновление ОС, смена аудиоустройства, аппаратная задержка, динамики и качество тембра на акустике пользователя не испытаны. Программные аудиочасы/PCM проверены отдельно на P4 и регрессией; они не доказывают физическую точность басиста.

История различает `screen-input` и `self-report`; время эталона не измеряет реальную игру. Резервная копия не защищает от утраты самого файла, а браузерное хранение не гарантирует сохранность профиля. Производительность долгой истории и предел 10 МиБ имеют отдельную синтетическую [пробу масштаба](../../experiments/p7-scale/README.md) и задачу P7-00; candidate этой пробы не объявляется выполненным продуктовым улучшением.

R-001/R-002/R-004/R-013/R-014 закрыты на основании этого набора и прежних отчётов; остальные требования MVP закрыты своими этапами и сохранёнными регрессиями. Следующий шаг — P7-00, затем ограниченные принятые R-016–R-020. Дальнейший диагностический аудиовход не равен автоматическому зачёту исполнения и имеет отдельный барьер реального устройства.
