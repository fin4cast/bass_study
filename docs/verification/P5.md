## Что проверено

| Сценарий | Наблюдение и предел вывода |

| Соседние записи | Очередь настроек/истории не теряет пресеты или старые результаты; upsert по ID и удаление затрагивают только нужную запись. |
| Экспорт и чистое восстановление | Настройки, два пресета и screen/manual совпадают после переноса в чистый контекст; полная замена удаляет лишнюю запись. |
| Отмена и валидация | Отмена, повреждённый JSON, чужой формат, будущая версия, неверные типы/значения, дубликаты и несогласованный экранный исход не меняют снимок. Проверка делается до транзакции. |
| Откат заполненной базы | Восстановление намеренно прервано через `transaction.abort()` после **одного успешного put**; `successfulWrites: 1`, `aborted: true`. Прежние настройки, пресеты и история совпали полностью, включая выполненные перед put очистки. |
| Нативная квота | CDP-лимит 1 байт для тестового origin вызвал реальный отказ IndexedDB с кодом `QUOTA`; исходный пустой снимок остался прежним. После снятия лимита новая запись сохранилась. Физический диск не заполнялся. |
| Полный перезапуск | Edge целиком закрыт и запущен снова с тем же изолированным профилем; снимок совпал. Для UTC `2026-11-08T22:30:00.000Z` в `Europe/Moscow` сохранилась исходная дата **2026-11-09**. |
| Настройки и пресеты в UI | Изменение/перезагрузка, сохранение, применение и удаление пресета работают; экспорт скачивает фактический JSON. Пресет содержит изучение, задания, последовательность и плеер. |
| Импорт в UI | Просмотр количества и предупреждение предшествуют замене; отмена сохраняет состояние; подтверждение заменяет весь снимок. Повреждённый файл показывает ошибку без потери данных. |
| Экранный результат | Завершённая серия записывается один раз, переживает дальнейшее сохранение настроек. Модель отдельно проверяет исходные попытки/ошибки прерванного вопроса, показ, пропуск и частичный «найди все». |
| Ручная практика | Сохраняется `self-report`, комфортный BPM и заметка, без accuracy/correct. Продолжительность получена от фактического эталона; после успешной записи повторное сохранение без новой практики не удваивает время. |
| История и повтор ошибок | Фильтры различают screen/manual. Повтор восстанавливает исходные тонику/структуру и точный набор ошибочных позиций; он не смешан с полным диапазоном. |
| Видимый отказ и повтор | Реальная ошибка квоты видна в UI; после снятия лимита «Повторить сохранение» записывает отложенный пресет. Успешный повтор убирает старое сообщение ошибки. Очередь отдельно проверяет, что посторонняя удачная настройка не скрывает неуспешную историю. |
| Отказ исходного открытия | В отдельном сценарии IndexedDB недоступна: UI явно показывает память страницы, позволяет занятие/экспорт и не сообщает о постоянном сохранении. Этот сценарий не служит доказательством нативного хранения. |

Модульные проверки дополнительно ограничивают размер копии 10 МиБ, проверяют plain JSON без accessor/разреженных массивов, уникальные идентификаторы, календарные значения, правила самостоятельного/исправленного ответа и группировку скорости только внутри сопоставимого контекста. Значения из копии не принимаются как готовая оценка без проверки событий.

## Уточнение проверки квоты

Первый вариант теста уменьшал квоту после заполнения базы и ожидал отказ любой маленькой записи. Эта предпосылка не подтвердилась: IndexedDB могла использовать уже зарезервированное пространство и принять запись. Это не доказывало отсутствие ошибки продукта. Финальная проверка квоты использует исходный пустой снимок и реальный браузерный отказ; отдельный сценарий с заполненной базой доказывает атомарный rollback после успешного put. Нельзя подменять эти два вывода друг другом или называть CDP-лимит заполнением физического диска.

## Представление и границы

История вынесена в свёрнутый раздел, чтобы гриф оставался главным экраном. Снимок `test-results/p5-history-desktop.png` просмотрен: источники результатов, ручная форма, пресеты, перенос и повтор ошибок различимы. Это не общая UX-приёмка всех диапазонов: при одном ладе исследовательский SVG выглядит чрезмерно крупным; адаптацию узкого диапазона проверить на P6.

Результаты относятся к Edge и указанным сценариям. Миграция между версиями схемы, импорт версии 1 в следующую, несколько одновременно пишущих вкладок, очистка данных браузером/ОС, Chrome/Firefox и скринридер пока не проверены. Браузерное хранение остаётся best-effort; внешний JSON нужен независимо от успешного автосохранения. Предел копии 10 МиБ задан явно; пользовательские аудиофайлы в неё не входят.

Длительность практики отражает работу эталона, не время реальной игры и не правильность исполнения. Самооценка комфортного BPM не превращается в измеренную точность. Ни история, ни PCM не доказывают качество техники, физическую задержку выхода или удобство тембра.
