# Работа с bass_study

Личный локальный тренажёр для 4-струнного баса E–A–D–G. Цель — Windows + Edge, клавиатура, один пользователь. Документация и интерфейс — по-русски; идентификаторы, названия технологий и форматов — как принято.

Этот файл — правила работы. Состояние проекта, история и результаты прогонов здесь не ведутся: состояние определяй по коду и `git log`, устройство — по [архитектуре](docs/ARCHITECTURE.md).

## Перед изменением

- Прочитай затрагиваемый код и относящиеся к нему разделы [требований](docs/REQUIREMENTS.md), [архитектуры](docs/ARCHITECTURE.md) и [решений](docs/DECISIONS.md). Весь комплект документов при каждой правке перечитывать не нужно.
- Делай то, что просили. Полезные идеи вне задачи записывай в [план](docs/PLAN.md), а не реализуй попутно.
- Сохраняй изменения пользователя в рабочей копии; не сбрасывай её ради чистого состояния.
- Новую зависимость добавляй только под реальный сценарий, проверив лицензию и условия поставки. Удаляя зависимость, докажи поиском, что она не используется.

## Документы

- Каждый факт живёт в одном месте: поведение — требования; устройство — архитектура; причины выбора — решения; порядок работ и отложенные идеи — план; внешние основания — исследование. В остальных местах — ссылки.
- Не записывай в документы счётчики тестов, даты прогонов, журналы изменений и состояние «на сегодня». Это есть в `git log` и в выводе команд.
- Стабильные ID (G-, R-, D-) не перенумеровывай. Заменённое решение помечай ссылкой на новое; отдельные ADR-файлы не создавай.
- Предложение в документах — не реализованная возможность. Не описывай будущее как сделанное и не приписывай проверок, которые не выполнялись (физический бас, USB-интерфейс, сквозная задержка пока не проверены).

## Инженерные правила

**Данные.**
- Один писатель: право записи держит одна вкладка (Web Locks). Две пишущие вкладки не допускаются.
- Импорт атомарен: предпросмотр ничего не меняет, подтверждённая замена выполняется одной транзакцией IndexedDB, при отказе база остаётся прежней. Откат проверяется отказом после уже успешного `put`, а не только до записи.
- Кеш снимка обновляется только после `complete` транзакции. Ошибка записи видна до успешного повтора; экспорт ждёт очередь и не выдаёт несохранённое за записанное.
- Одна испорченная запись не должна делать недоступной всю базу. При чтении своей базы проверяется форма записей; полная проверка с повтором ответов — для импорта.
- Пока у приложения один пользователь и данные не ценны, цепочку миграций не ведём. Меняя схему, повышай версию IndexedDB: при апгрейде хранилища пересоздаются пустыми. Версию никогда не уменьшай — `indexedDB.open` с меньшей версией даёт `VersionError`. Формат резервной копии — только текущий.
- Тестовых крючков в продуктовом коде нет: отказы и наблюдение подставляются через параметры фабрик и фикстуры.

**Звук.**
- Разделяй план, фактический сигнал, PCM и интерфейс. Запланированное событие — ещё не прозвучавшее: исключай отменённые и сравнивай время с часами `AudioContext`.
- Звучание проверяется на PCM (`OfflineAudioContext` или запись). Физическую задержку и качество тембра из PCM не выводи.
- Одновременно звучит один владелец звука; координация — в `src/app/audio-owner.ts`.

**Интерфейс.**
- Данные пользователя и файлов не попадают в разметку без экранирования.
- Скрытый тестовый API с правильными ответами не создаётся; ответы скрыты и в ARIA.

## Проверки

Команды (Node 24, Edge установлен):

```powershell
npm run check          # типы
npm test               # unit (Vitest)
npm run build          # сборка
npm run docs:check     # ссылки и якоря документации
npm run test:regression # быстрый набор: всё выше + браузерные сценарии в Edge и PCM-проверки
npm run test:full       # полный набор: + настоящие скрытые вкладки и визуальные матрицы на всех ширинах
```

- Между изменениями кода — первые четыре команды и быстрый `test:regression`. Перед push — `test:full`; CI запускает его же. Изменение только документации — `docs:check` и `git diff --check`.
- Сценарии только полного набора в быстром отчёте помечены `skipped` с причиной. Новый сценарий относится к полному набору, только если это настоящая скрытая вкладка Edge или дополнительная ширина визуальной матрицы ([подробнее](docs/DEVELOPMENT.md#regression)).
- Исправленный дефект закрывается тестом, который краснеет без исправления. Удаляешь код — удаляй и тесты, проверяющие только его.
- Результаты прогонов остаются в `test-results/` (игнорируется git) и в артефактах CI. Отчёты, снимки экрана и JSON прогонов в репозиторий не коммить.
- `test:regression` и `test:full` запускают браузерные раннеры параллельно, каждый со своими серверами на портах от ОС. Чужой запущенный сервер не останавливай.
